# 摸鱼bot · QQ 记事与文件助手

在电脑上运行 QQ 机器人：记下待办和灵感、搜索旧记录、把电脑里的文件发到 QQ。待办和灵感保存在本机；使用时电脑需要开着。

## 快速开始

### 普通用户：安装版

1. 从 [最新版下载页](https://github.com/phononprismlab/memo-bot/releases/latest) 下载 Windows 安装包并按提示安装。
2. 打开“摸鱼bot”，在“配置中心 → ① 连接 QQ”填写 QQ 开放平台提供的 AppID 和 AppSecret。
3. 点“保存凭据”，再到“⑦ 运行方式”点“启动”。
4. 要在群里使用时，把机器人拉进群，并在 QQ 群设置中开启“获取群内全部消息”和“机器人主动在群聊内发言”。配置中心也会显示这两项的提示。
5. 在群里发 `待办 测试`。要私聊使用，请先在 QQ 开放平台开启单聊，并先向机器人发起私聊。

### 从源码运行

需要先安装 Python 和 pip。在项目目录运行：

```bash
pip install -r requirements.txt
python memo-launcher.py --gui
```

首次打开后，按上面的步骤填写凭据并启动机器人。

其余配置——触发词、发文件的搜索目录、开机自启、忽略表——**都在配置中心那一页上**，不用碰 `.env`，也不用记命令。

## 能力

1. **待办（我要做）**：群消息以「待办」开头就会记下来并回复你；记录保存在本机。  
   在[脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)页上**完成 / 取消完成 / 丢弃**。
2. **灵感（我的想法）**：群里**非 @** 的普通发言、以及**私聊里的任意非指令文本** → 自动收作 `idea`（**静默记录，不打扰**）。  
   写灵感时带 **`#` 号**：`#` 后面的内容会自动变成**标签**（空格 / 标点分隔多个），发「搜索灵感 <标签名>」就能按标签找回。
3. **脑内抽屉**：桌面窗口里的「脑内抽屉」页签，把**待办（待办）+ 思绪（灵感）**&#x653E;成不停往上飘的卡片，  
   **点一下直接写库** —— 待办完成 / 取消完成 / 丢弃、思绪整理 / 取消整理 / 丢弃、写错的正文随时改（创建时间不变），不用导出任何文件（见 [脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)）。
4. **发**：把本地文件经机器人发送到指定**群 / 私聊**；文本类文件**渲染成图片**发送。
5. **上线播报 / 新手引导**：**第一次**连上时在群里发一段「功能介绍」（自我介绍，并写明**没有语言生成能力**），  
   之后每次启动只发一句「我上班了，开摸！」。两段文案都在配置中心里改（见 [配置](#配置三个入口)）。
6. **摸鱼**：发「摸鱼」→ 从内置库里随机抽一条放松动作 / 摸鱼点子，帮忙从工位上分神 30 秒。
7. **配置中心**：桌面窗口里的「配置中心」页签，填凭据 / 选目录 / 开自启 / 启停机器人 / 看依赖 / 装依赖，  
   **不用碰 `.env`、不用记命令**（见 [配置中心](#配置中心桌面窗口)）。
8. **设置**：`设置` / `设置 <键> <值>` —— 在群里也能改本机配置（启动播报、脑内抽屉展示范围），  
   **与桌面配置中心写同一份文件**。
9. **回旋镖**：发「回旋镖」→ 从「N 天以前」的旧记录里**随机翻一条推回来**，提醒你回头看当时的待办 / 灵感（有结论的会连结论一起推）。  
   抽出来的卡片会**放回池子**（同一条能被反复抽到）；回溯天数与「翻哪几类」都在配置中心里调。
10. **导出**：发「导出」→ 把**全部待办 + 灵感**导成一个文件发回给你（md / txt / json，默认 md）；  
    脑内抽屉底部也有「导出」按钮 —— 两边导出的排版一模一样。
11. **常用指令**（群聊和私聊都能用）：

| 你发                     | 它会做什么                     |
| ---------------------- | ------------------------- |
| `待办 内容`                | 记下一条待办                    |
| `查待办` / `查灵感`          | 查看最近的待办 / 未整理的思绪          |
| `搜索灵感 关键词`             | 按正文、标签或结论查找思绪             |
| `发文件 关键词`              | 在配置的文件夹里查找并发送文件           |
| `摸鱼` / `回旋镖`           | 抽一条放松内容 / 翻回一条旧记录         |
| `导出 [md/txt/json/zip]` | 导出待办和思绪                   |
| `忽略 内容`                | 跳过包含该内容的消息；发 `忽略 列表` 查看规则 |
| `设置`                   | 查看可通过聊天修改的设置              |
| `帮助` / `你好`            | 查看指令 / 功能介绍               |

群里不 @ 机器人时，普通发言会保存为灵感；私聊里非指令文本也会保存。群里查询的回复所有群成员都能看到，私事请在私聊中查询。

### 忽略不想收的消息

如果群里还有其他机器人，可以把它的名字加入忽略表。匹配的消息不会保存成灵感，也不会触发回复。用 `忽略 列表` 查看规则，用 `忽略 删除 内容` 或 `忽略 清空` 管理。

## 配置中心（桌面窗口）

打开“摸鱼bot”后，在“配置中心”页签管理凭据、播报、文件搜索目录、运行方式和其他设置。菜单名称与程序一致：

| 分区      | 用途               |
| ------- | ---------------- |
| ① 连接 QQ | 填写凭据、选择播报对象      |
| ② 群内行为  | 设置待办触发词、回执和忽略规则  |
| ③ 播报    | 修改启动播报与首次介绍      |
| ④ 发文件   | 选择查找文件的文件夹       |
| ⑤ 脑内抽屉  | 选择内容流类别、调整界面字号   |
| ⑥ 回旋镖   | 设置回溯天数和记录范围      |
| ⑦ 运行方式  | 启动、停止、重启机器人和开机自启 |
| ⑧ 摸鱼库   | 修改或恢复随机抽取的内容     |
| ⑨ 自定义指令 | 导入、查看和移除指令包      |
| ⑩ 版本    | 查看版本、检查和下载更新     |

🔴 **一次只显示一块**：上面这些分区是**左侧分区导航**，点一个看一块，不用一路往下拉。  
**凭据没填全时**只留「① 连接 QQ」那一块能进 —— 填好 AppID / AppSecret 再往下配。

🔴 **「① 连接 QQ」页里有一块「去 QQ 里开两个开关」的提醒**（群聊消息范围 = 获取群内全部消息、机器人主动在群聊内发言 = 开）。  
这两项**在 QQ 那边管，配置中心改不了**，但不开的话机器人收不到群里的普通发言、也发不出播报，用户会以为「机器人坏了」——  
所以直接摆在连接页上，不指望人家去翻安装指南。

改摸鱼库**不用重启机器人**：保存完下次发「摸鱼」就是新的。改凭据 / 触发词 / 搜索根才要重启。

窗口顶部常驻状态：机器人是否在跑（含 pid）、开机自启是否已开。

### 🔴 三条硬规则

- **只在本机窗口里用** —— 它直接读写 `.env`（含密钥），**没有任何网络端口 / 网页服务**，不存在对外暴露面。
- **AppSecret 不回显** —— 已保存的密钥留空 = 不改；要换就重新填一遍。
- **写 `.env` 是按行改** —— 你手写的注释与顺序原样保留，已有键只换值，新键追加到末尾；  
  写前自动备份成 `.env.bak`（已 gitignore）。路径里的反斜杠会自动转成正斜杠；多个搜索目录会自动去重。

> 改完**凭据 / 触发词 / 搜索目录**要重启机器人才生效 —— 「⑦ 运行方式」里有「重启」按钮。  
> 改**文案 / 展示范围**同样建议重启（文案是 bot 启动时读的）。

## 配置：三个入口

`settings.json` 是「非敏感的行为配置」，三个入口改的都是它：

| 入口        | 怎么用                                          | 放哪些                  |
| --------- | -------------------------------------------- | -------------------- |
| **配置中心**  | 桌面窗口「配置中心」页签里填                               | 全部（含 `.env` 里的凭据与路径） |
| **脑内抽屉页** | 桌面窗口「脑内抽屉」页签的「脑内抽屉」分区（界面字号 / 内容流放哪几类）        | 只有跟当前页面强相关的几项        |
| **机器人**   | `设置` 看全部 · `设置 <键> <值>` 改 · `设置 重置 <键>` 恢复默认 | `settings.json` 里的键  |

- **取值优先级**：`settings.json` → 同名环境变量（`.env`）→ 内置默认值。  
  只把**显式改过**的键写进文件，所以老配置（`.env` 里的 `QQ_STARTUP_MSG`）不会失效，继续当回退值。
- 🔴 **密钥不进 `settings.json`** —— AppID / AppSecret 仍留在 `.env`；设置内容会显示在本机配置中心或机器人回复里，不放秘密。
- 🔴 **`settings.json` 已 gitignore**（含本机文案 / 群内信息）。

`settings.json` 里的键：

| 键                 | 中文名      | 类型   | 默认值                                     |
| ----------------- | -------- | ---- | --------------------------------------- |
| `startup_msg`     | 启动播报     | 文本   | `我上班了，开摸！`（留空 = 不播报）                    |
| `intro_msg`       | 功能介绍     | 多行文本 | 一段自我介绍，**写明「没有语言生成能力」**；首次上线自动发、「你好」也回它 |
| `memo_ack`        | 待办回执     | 文本   | `已经放进脑内抽屉了`（留空 = 静默记下）                  |
| `idea_ack`        | 灵感回执     | 文本   | 空 = 静默收下。填一句就回，例如 `💡 已收作灵感`            |
| `bubbles_show`    | 脑内抽屉展示范围 | 多选   | 待办 + 待处理                                |
| `ui_font_scale`   | 界面字号（%）  | 整数   | `115`（80 ~ 200；100 = 原始大小，整窗缩放，保存后立刻生效） |
| `boomerang_days`  | 回旋镖回溯天数  | 整数   | `3`（1 ~ 365；刚记的还不算）                     |
| `boomerang_scope` | 回旋镖推送范围  | 多选   | 待办 + 未整理 + 已整理（不含「已丢弃」）                 |

> 配置中心的分区顺序、`设置` 指令列出的顺序，都按上表排。

- 文本类：直接写值；`设置 重置 <键>` 从文件里删掉该键 → 回到 env / 默认值。
- 多选类：值可写 code 或**中文标签**（例如 `设置 bubbles_show 待办,未整理的思绪`），认不出会拒绝并列出可选项。
- 整数类：只收整数，超范围会被拒绝并告诉你上下限（`设置 boomerang_days 7`）。
- 指令词后面**必须有分隔符**（空格 / `：` / `:`）—— 否则「设置好了」「配置一下」这种普通聊天会被误判成指令（这类消息照常当灵感收下）。
- 桌面配置中心会先校验再保存：有一项填错时整批不写入；只保存实际修改过的项目。

## 私聊（单聊）支持

群与私聊走**同一套指令与识别逻辑**，私聊里不需要 @。

- **平台侧要开**：QQ 开放平台 → 开发设置 → 功能配置，开启「单聊」能力（沙箱与正式环境各自配置）；用户需先与机器人建立单聊会话。
- **私聊里的行为**：
  - 内置指令（`待办` / `查待办` / `查灵感` / `发文件` / `摸鱼` / `回旋镖` / `导出` / `忽略` / `帮助`）与扩展指令都可用；`发文件` 用宽松别名（`发 设计说明` 也行）。
  - **非指令文本**一律静默收作「灵感」（私聊没有「打扰群」的顾虑）。想要回执，在**配置中心 → ② 群内行为 → 灵感回执**里填一句（例如「💡 已收作灵感」）；留空就是静默收下。
  - 私聊里发文件 / 发图走**被动回复**（带触发消息的 `msg_id`）—— 用户刚发来一条指令，回给「那条消息」语义更准，也不占主动消息额度。
- **存储**：私聊记录落同一张 `memos` 表，`group_id` = `c2c:<user_openid>`、`group_name` = `私聊`，与群记录互不干扰。
- **技术**：`C2C_MESSAGE_CREATE` 由 botpy 1.2.1 **原生解析**（无需像群全量消息那样补解析器）；intents 仍是 `public_messages=True`（它同时覆盖群与 C2C）。
- **命令行发私聊**：`python send_file.py --file <路径> --user <user_openid>`（单聊无主动权限，自动走被动回复）。

### 几个文件的内部要点

- `bot.py`
  - 路由主体是**模块级** `route_message(client, message, mentioned, scope)`（不在 `main()` 内的类里），便于回归测试直接驱动；`MemoClient.route()` 只是转发。
  - 运行时用 `install_group_message_parser()` 给 botpy 补上 `GROUP_MESSAGE_CREATE` 解析器（官方 1.2.1 未注册该事件，会被网关丢弃）；`C2C_MESSAGE_CREATE` 官方已注册，无需补。
  - `--log <文件>` 把 stdout/stderr 与 logging 重定向到文件，供 `pythonw.exe` 无控制台常驻运行。
- `send_file.py`：群 / 单聊由 `scope` 切换（`--group` / `--user`）；**默认主动推送**（群需开启「机器人主动发言」；单聊无需开关，实测可主动推送），群内主动失败会自动降级被动回复，`--passive` 可强制被动。上传带 `file_name`（否则 QQ 文件卡片显示「未命名」），并对 `305013`（审核服务超时）/ `850027`（发送超时）/ `40093001`（上传失败）**自动重试 2 次**。
- `config_core.py`：`ENV_SPEC` 是**白名单** —— 界面只能改表里列出的键；写 `.env` 按行改（注释与顺序保留），多目录字段自动归一成「分号串 + 正斜杠」并去重；`_powershell()` 强制 UTF-8 输出且 `ErrorActionPreference='Stop'`（否则注册计划任务失败会被误报成成功）。
- `memo_gui.py`（脑内抽屉页）：**待办和思绪混在一条流里**，每条带一个「桶」（`memo` / `memo_done` / `open` / `done` / `decided` / `dropped`），分流 / 配色 / 计数全按桶走。  
  🔴 **「已完成 / 已整理」是终态，边框统一灰色**；「待办」「思绪」点开的是**列表窗口**，在列表里点一行打开「思绪卡片」浮层（**列表不关**，方便接着翻）。  
  ✏️ **每条都能改正文**（`store.update_content`）—— **创建时间不变**；永久删除（`store.delete_items`）**只在回收站里确认着点**。  
  🔴 气泡 / 卡片正文的长英文 / 路径用 `_soft_wrap()` **按像素预折行**（Tk 的 `wraplength` 只认空格，长路径会被从中间硬砍）。

## 发送格式：文本类文件渲染成图片

**手机端文件卡片常打不开**（尤其 `.md` 这类无默认应用的类型），而把内容拆成多条文本消息又太碎。因此：

| 文件类型                                                         | 发送方式                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 文本类（`.md/.txt/.json/.py/.js/.csv/.log/.html/.yml` 等）且 ≤150KB | **渲染成图片发送**（Markdown 转 HTML → Chrome 截图 → `file_type=1`），手机端原生可看、可缩放、保留排版 |
| 图片 / 视频 / 语音                                                 | 对应富媒体（手机原生可看）                                                             |
| 其他二进制 / 超大文本                                                 | 文件卡片（`file_type=4`）                                                       |

- 渲染链路：`md2img.py`（Python `markdown` 库 → HTML）→ `md2png.mjs`（Node + `playwright-core` 用系统 Chrome 截图）。
- 默认**单张长图**（宽 760 CSS px、dpr=2）；整篇超过 14000 CSS px 才自动分页。
- 🔴 **正文里的相对路径图片**靠注入 `<base href="{源文件目录}/">` 加载（HTML 写在临时目录，否则图片全部不显示）；正文图片限高 600px。
- CLI：`--as-text` 强制文本直发、`--as-file` 强制文件卡片。
- 🔴 被动回复的 `msg_seq` 在 bot（1~3）与 CLI（从 100 起）之间**必须错开**，否则同一 `msg_id` 会撞 `40054005 消息被去重`。

## 待办 vs 灵感

**一句话区分：待办 = 我要做，灵感 = 我的想法。**

|    | 是什么      | 触发                         | 落库 `kind` | 处理方式                                                                  | 是否回执         |
| -- | -------- | -------------------------- | --------- | --------------------------------------------------------------------- | ------------ |
| 待办 | **我要做**  | `@bot 待办 xxx`，或任意位置以「待办」开头 | `memo`    | 三态：**没完成 / 已完成 / 已丢弃**（在[脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)页上点勾选框或丢弃） | 回「已记到秘书会话 ✅」 |
| 灵感 | **我的想法** | 群里**非 @** 的普通发言            | `idea`    | 四态：待处理 / 已处理 / 已决议 / 已丢弃                                              | **不回执**（静默）  |

- **待办的 `status` 有三态**：`open`（没完成）/ `done`（已完成）/ `dropped`（已丢弃），改状态时间记在 `processed_at`。  
  🔴 待办**没有 `decided`** —— 它是「我要做」，要么做完，要么不做了。
- 🔴 **「已丢弃」是两类共用的桶**：丢弃的待办和丢弃的灵感都进同一个列表，列表里可以「← 恢复」或「🗑 永久删除」。
- ✏️ **两类都能「再次编辑」正文**：回顾时发现写错字、或对某件事有了新想法，随时改 —— **创建时间不变**（时间轴不会乱）。
- **灵感的 `status` 有四态**：

| 状态        | 含义              | 导出标记  |
| --------- | --------------- | ----- |
| `open`    | 待处理             | `[ ]` |
| `done`    | 已处理（产生了行动并完成）   | `[x]` |
| `decided` | 已决议（有结论，但不产生行动） | `[~]` |
| `dropped` | 已丢弃（不成立 / 无效）   | `[-]` |

- 两者都存在同一张 `memos` 表里、同一个[脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)页面上，  
  靠「桶」（`memo` / `memo_done` / `open` / `done` / `decided` / `dropped`）分流。

`查待办` / `查灵感` 分别只看对应类别（`查灵感` 只列 `open`）；`python bot.py --list` 打印全部并标注类别。

## 灵感池：给「专门处理灵感的会话」用的入口

灵感是碎片，需要在电脑上集中处理（评估 → 做/不做 → 留结论）。`ideas.py` 提供这个闭环：

```bash
python memo-bot/ideas.py --export              # 导出「待处理」灵感 → 工作区 灵感池.md（逐条编号）
python memo-bot/ideas.py --list                # 终端列出待处理（--all 看全部）
python memo-bot/ideas.py --done 1,3 --note "已做成 X"   # 标记处理完（有行动）
python memo-bot/ideas.py --decide 4 --note "结论：不做 X"  # 标记已决议（有结论、无行动）
python memo-bot/ideas.py --drop 2 --note "与现有方案重复"  # 标记丢弃
python memo-bot/ideas.py --stats               # 只看计数
```

- **序号**（`1,2,3…`）相对**当前待处理列表**，每次 `--export` 后固定；也支持传 id 前 8 位。
- 处理过的灵感从「待处理」消失、进 `灵感池.md` 的归档区，**不会被重复捞**。
- 存储字段：`status`（open/done/decided/dropped）+ `note`（结论）+ `processed_at`（处理时间）。

> 新会话开场直接说「处理灵感」即可 —— 项目记忆里已登记这条入口。

## 摸鱼库：群内发「摸鱼」随机歇一下

内容全部是**本地静态库**（内置 65 条），不调 AI、不联网、零延迟。

| 指令                  | 结果                             |
| ------------------- | ------------------------------ |
| `摸鱼` / `放松` / `歇会儿` | 抽 1 条（**默认池 = 放松 + 摸鱼，不含冷知识**） |
| `摸鱼 3` / `摸鱼 3 条`   | 一次抽 3 条（上限 5 条）                |
| `摸鱼 冷知识`            | 只抽冷知识                          |
| `摸鱼 3 冷知识`          | 条数与分类可组合                       |
| `摸鱼 全部`             | 三类混抽                           |

### 改内容：两份库，一份种子一份你的

| 文件               | 是什么                | 谁写它               |
| ---------------- | ------------------ | ----------------- |
| `moyu-data.json` | **内置库（只读种子）**，随代码走 | 只读。程序**永远不写它**    |
| `moyu-user.json` | **你自己那份**，落在数据目录   | 配置中心「⑧ 摸鱼库」页签保存时写 |

- **生效规则**：数据目录里有 `moyu-user.json` 就用它，没有就用内置库。
- **怎么改**（三种，改的都是同一份）：配置中心「⑧ 摸鱼库」页签（推荐）、直接编辑 `moyu-user.json`、删掉 `moyu-user.json` = 恢复内置。
- 🔴 内置库只当种子。源码版的数据目录就是代码目录，所以**不能**直接往 `moyu-data.json` 写，否则会把跟着版本走的库覆盖掉。
- 用户库读坏了 / 是空的 → **悄悄退回内置库**，不会让「摸鱼」整个哑掉。
- 改完库会**清空**「最近抽过哪些」的记录（`id` 是位置编号，换内容后含义就变了）。

### 🔴 指令识别是「宽容」的，不是精确匹配

群里没人会规规矩矩打「摸鱼」两个字。识别走 **归一化 → 前缀匹配 → 参数解析** 三步：

| 你打的                 | 归一化后         | 结果             |
| ------------------- | ------------ | -------------- |
| `摸鱼！` `摸鱼~` `摸鱼。`   | `摸鱼`         | ✅              |
| `摸摸鱼`               | `摸鱼`（重复字压缩）  | ✅              |
| `想摸鱼` `来点摸鱼` `该摸鱼了` | `摸鱼`（剥前置语气词） | ✅              |
| `摸鱼吗` `摸鱼吧` `摸鱼一下`  | `摸鱼`（剥后置语气词） | ✅              |
| `摸个鱼`               | 同义词表         | ✅              |
| `摸鱼 3 条`            | `摸鱼3条`       | ✅ 抽 3 条        |
| `今天不想摸鱼了`           | —            | ❌ 不是指令（句中，不触发） |

- **@ 机器人**时若参数不认识（如 `摸鱼 来点啥`），回一句参数提示；  
  **非 @** 时不打扰群聊，按普通发言处理。
- **防重复**：最近抽过的 20 条记在 `moyu-recent.json`，抽的时候排除；某个池快抽完一轮就重置。
- 保存时校验：三类不能全空、单条最长 120 字、每类最多 200 条（防手滑粘进来一整本书）。
- CLI：`python moyu.py` / `python moyu.py 3` / `python moyu.py --cat trivia` / `python moyu.py --parse "摸鱼！"` / `python moyu.py --stats`。

## 回旋镖：把旧账翻回来

记下来的东西容易沉底。发一条「回旋镖」，机器人就从**N 天以前**的记录里随机挑一条推回给你。

| 指令      | 结果                       |
| ------- | ------------------------ |
| `回旋镖`   | 用配置里的回溯天数（默认 3 天）翻一条     |
| `回旋镖 7` | 只看 7 天以前的                |
| `回旋镖 0` | 今天记的也翻 —— **刚上手第一发就有反应** |
| `回旋标`   | 别名，一样能用                  |

- **哪发的指令就推回哪**：群里发就回群里，私聊发就回私聊。
- **抽出来的卡片放回池子**：池子恒定不变，同一条记录可以被反复抽到（连着两次抽到同一张也算数），  
  所以不存在「推过一轮就没了」——只要范围内有满天数的记录，每次发「回旋镖」都有回应。
- 🔴 **回溯天数可以填 0**（配置中心「⑥ 回旋镖」里改，或 `设置 boomerang_days 0`）：填 0 就是  
  **今天记的也算**，刚试用的用户发一句「回旋镖」立刻能看到效果，不会被「还没满 3 天」挡在门外。
- **推哪几类、往前翻几天**：在配置中心「⑥ 回旋镖」里调（也能用 `设置 boomerang_days 7` /  
  `设置 boomerang_scope 待办,未整理的思绪`）。**分类与「⑤ 脑内抽屉」的展示范围完全一致** ——  
  待办 / 已完成的待办 / 未整理的思绪 / 已整理的思绪 / 已丢弃，默认前四类，**不含「已丢弃」**。
- 挑中的是**灵感**且当时留了结论时，会把「【当时的结论】…」一并推给你。

发「导出」→ 机器人把库里所有待办和灵感排成一个文件发回来。

| 指令             | 结果                                                 |
| -------------- | -------------------------------------------------- |
| `导出` / `导出 md` | Markdown（默认）：正文放引用块，换行原样保留                         |
| `导出 txt`       | 纯文本，按类别分节                                          |
| `导出 json`      | 结构化，带 `exported_at` / `counts` / `memos` / `ideas` |

## 脑内抽屉：把「我要做」和「我的想法」放成一个轮播页面（实时处理端）

桌面窗口「脑内抽屉」页签读 `memos.db`，把**待办 + 思绪**渲染成不停往上飘的卡片轮播（原生窗口，不再开浏览器）。

> **为什么叫「抽屉」**：这里装两类东西 ——  
> **待办 = 我要做**（待办：未完成 / 已完成 / 已丢弃）；  
> **思绪 = 我的想法**（灵感：未整理 / 已整理 / 已丢弃）。  
> 以前待办只有群指令、没有界面，处理链路是断的；现在补上了。

进入方式：跑 `python memo-launcher.py --gui`，切到「脑内抽屉」页签。  
底部有「思维流 / 待办 / 思绪 / 标签 / 刷新 / 回旋镖 / 导出 / 回收站」；  
点「待办」「思绪」开**列表窗口**（可按未完成 / 已完成、未整理 / 已整理再筛），点一行打开**思绪卡片**浮层处理。

### 第一次打开：会有几条示例，不会是一片空白

库**第一次建出来**的时候（不管先跑的是机器人还是这个页面），会自动放 **4 条示例**：

| 类型    | 内容大意                                        |
| ----- | ------------------------------------------- |
| 灵感 ×3 | 群里随手发一句就收成灵感（不用 @）/ 点卡片就能处理 / 发「回旋镖」把旧记录翻回来 |
| 待办 ×1 | 在群里发「摸鱼」，随机回你一条摸鱼文案                         |

- 它们就是**普通记录** —— 能编辑、能完成、能丢弃、能永久删除，跟你自己记的没有任何区别。看懂了随手点掉就行。
- 🔴 **只在库是全新的时候塞一次**：判据是 `memos` 表此前**不存在**（不是「表是空的」）。  
  所以老库绝不动，示例被你删光/处理光之后也**不会**又给你塞回来。
- 想要一个干净的库：设 `MEMO_NO_SEED=1`（见 `.env.example`）。

### 视图：内容流放哪几类由设置决定

内容流默认展示未完成的待办和未整理的思绪。底部可以打开待办、思绪列表，按状态继续筛选；也可以按标签筛选或直接搜索。

- 搜索会匹配正文、标签和结论；写灵感时加入 `#设计` 这样的标签，之后可以按标签找回。

### ✏️ 再次编辑正文：改内容，不改时间

回顾时发现写错字，可以直接编辑，不用删掉重记。

- 点卡片打开详情，再点“编辑”，修改内容后保存或取消；从列表打开卡片时，列表会保持打开。

永久删除只在回收站里操作。程序会先显示确认提示；确认后记录无法恢复。

### 实时查看

脑内抽屉和机器人读取同一份本地记录。机器人收到新内容后，点“刷新”即可更新；列表较长时可点“加载更多”。

## 可扩展性：加你自己的指令

内置指令之外，你可以**不改任何公开代码**就加自己的指令 —— 放在 `extensions/local/` 即可。  
该目录已在 `.gitignore` 里，**不会进公开仓库**（本地 bot = 公开代码 + 你的私有扩展）。

### 两种装法

| 形态       | 长什么样                                                | 怎么来                           |
| -------- | --------------------------------------------------- | ----------------------------- |
| **单文件包** | `extensions/local/myext.py`                         | 自己写，或在配置中心「⑨ 自定义指令」导入一个 `.py` |
| **指令包**  | `extensions/local/myext/`（里面放一个或多个 `.py`，可带自己的数据文件） | 在配置中心「⑨ 自定义指令」导入一个 `.zip`     |

桌面配置中心的「⑨ 自定义指令」页负责**导入 / 列出 / 移除**——  
这也是把指令分享给别人的路子：你写好 → 打包成 `.py` 或 `.zip` → 别人在配置中心导进去 → 重启机器人即可用。  
移除只是把文件挪进 `extensions/.removed/`，不是真删。

### 三步加一条指令

1. 在 `extensions/local/` 新建 `myext.py`；
2. 写一个 `register(reg)`；
3. 重启 bot，`帮助` 菜单会自动带上你写的 `help` 行。

```python
# extensions/local/myext.py
def register(reg):
    def handle(text, mentioned):
        return "👋 你好，这是一条自定义回复"
    reg.add(["打招呼", "hi"], handle, help="打招呼 —— 回你一句")
```

### handler 契约

```python
def handle(text, mentioned) -> str | list[str] | None
```

| 参数 / 返回        | 含义                            |
| -------------- | ----------------------------- |
| `text`         | 已剥掉 @ 标记的指令全文（如 `"我的指令 参数"`）  |
| `mentioned`    | 是否在 @机器人 场景（非 @ 时群里普通聊天也会走到这） |
| 返回 `None`      | 不处理，继续走后面的逻辑                  |
| 返回 `str`       | 回一条消息                         |
| 返回 `list[str]` | 依次回多条（`msg_seq` 自动递增）         |

- handler 是**同步函数**，框架用线程执行 → 里面可以直接做阻塞操作（读硬件 / 调外部命令），**不会卡住机器人心跳**。
- 想在非 @ 场景不接话？在 handler 里 `if not mentioned: return None`。

### 常用能力

| 通过 `reg`                           | 说明                                       |
| ---------------------------------- | ---------------------------------------- |
| `reg.add(names, handler, help="")` | 注册指令（`names` 为 str 或 list[str]，**精确匹配**） |
| `reg.api.search_files(q, limit=5)` | 按文件名/路径模糊搜配置的根目录                         |
| `reg.api.SEARCH_ROOT`              | 当前搜索根                                    |

### 加载与容错

- `extensions.load()` 依次加载 `extensions/*.py`、`extensions/local/*.py` 与 `extensions/local/<包名>/*.py`。
- 某个扩展导入失败 / `register()` 抛异常 → **只打印 warning，不影响 bot 启动**，其余扩展照常生效。  
  （配置中心的「⑨ 自定义指令」页会把失败原因直接显示出来。）
- 精确匹配时**后注册者优先**，所以私有扩展可以覆盖公开扩展的同名指令；页面会把「撞名」标出来。
- 判「什么算一个扩展包」的规则只有一处：`extensions.scan_dir()` —— 加载器与配置中心共用它，别各写一份。

完整模板见 `extensions/example.py`；本机私有扩展清单见 `extensions/local/README.md`；  
**要发布给别人用之前，照 `packaging/摸鱼bot-开发者说明.md` 逐条过一遍**（handler 契约、执行顺序、导入闸门、打包与自测清单都在那）。

## 真实部署（在你的本机，电脑需开机）

1. 安装依赖：`pip install -r requirements.txt`
   - 注意包名是 **`qq-botpy`**（`pip install botpy` 会失败）；导入名是 `botpy`。
2. **配置**（两条路选一条）：
   - ✅ **推荐**：`python memo-launcher.py --gui` → 桌面窗口「配置中心 → ① 连接 QQ」填 AppID / AppSecret → 点「保存凭据」；

   - botpy 登录用 **AppSecret（机器人密钥）**，不是 Token。
3. 把机器人加入你的群，并在**群设置**里打开下面那两个开关。想用**私聊**，还要在 QQ 开放平台 → 功能配置里开启「单聊」。
4. 启动常驻：`python bot.py`（或在桌面「⑦ 运行方式」里点「启动」）。

   勾上就收得到启动播报，不用自己去日志里抄 openid。
5. 发文件（默认主动推送，无需先 @）：  
   `python send_file.py --file <路径> --caption "说明"`

### 开机自启（不绑定任何会话）

用 Windows 计划任务托管，登录即启动，且**不显示控制台窗口**（`pythonw.exe` + `--log` 写文件）。

> ✅ **最省事的做法**：打开桌面「配置中心 → ⑦ 运行方式」→ 拨一下「开机自启」开关。  
> 它做的就是下面这段 PowerShell（等价），而且会实时显示当前是开还是关。

<details>

```powershell
# pythonw 路径：优先取 PATH 上的；否则改成你本机的 pythonw.exe 绝对路径
$py  = if (Get-Command pythonw -ErrorAction SilentlyContinue) { (Get-Command pythonw).Source } else { '<你的 pythonw.exe 路径>' }
$dir = '<仓库>\memo-bot'
$act = New-ScheduledTaskAction -Execute $py -WorkingDirectory $dir `
       -Argument ('-u "' + $dir + '\bot.py" --log "' + $dir + '\bot.out.log"')
$trg = New-ScheduledTaskTrigger -AtLogOn
$set = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
       -StartWhenAvailable -ExecutionTimeLimit ([TimeSpan]::Zero) `
       -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) -MultipleInstances IgnoreNew
Register-ScheduledTask -TaskName 'MoyuBot' -Action $act -Trigger $trg -Settings $set -Force
```

</details>

- 任务名 `MoyuBot`；查看状态：`Get-ScheduledTask -TaskName MoyuBot`；立刻跑：`Start-ScheduledTask -TaskName MoyuBot`。
- 日志：`memo-bot/bot.out.log`。
- 🔴 **同一时刻只能跑一个实例**（两个进程会各建一条 WS 连接、事件被抢）。改代码后要 `Stop-ScheduledTask` 再 `Start-ScheduledTask`（或配置中心点「重启」）。

## 两个入口为什么能并存

`bot.py`（收）走 WebSocket 网关常驻；`send_file.py`（发）走**纯 HTTP**（直接调 REST API，不建网关连接）。互不抢连接，可同时运行。

## 限制与注意

> 下面这几项开关都在**手机 QQ 的机器人设置页**里，具体位置见 [快速开始](#快速开始) 第 3 步的截图。

- **主动推送**：群需开启「机器人主动在群聊内发言」；**单聊无需开关**（实测可直接主动推送，有频控：个人认证 10/qps，未认证 5/qps + 30/qpm，单用户 20/qpm、每好友每天最多 1000 条）。群内未开启时会自动降级为被动回复（需 4 分钟内群里 @ 过 bot，`msg_id` 缓存在 `last_group_msg.json`）。`--passive` 可强制走被动回复。
- **全量群消息**：需群内开启「消息范围 = 全部消息」，且依赖 `install_group_message_parser()` 补的解析器。
- **私聊**：需在 QQ 开放平台开启「单聊」能力，且**对方要先私聊过机器人（并加了好友）** —— 这样才会出现在配置中心的「播报目标」列表里，也才有 `user_openid` 可发。私聊**可以主动推送**（见上条），所以启动播报能直接私聊发过去；只是**群指令的回复**（发文件 / 发图）走被动回复，语义更准。
- 本地文件上传走官方 `/v2/{groups|users}/{openid}/files` 的 `file_data`(base64) 参数；200MB 上限。**群与单聊的上传接口相互独立，不能跨场景使用**。
- 上传必须带 `file_name`，否则 QQ 文件卡片显示「未命名」；`305013`（审核服务超时，**不是内容违规**）/ `850027`（发送超时）/ `40093001`（上传失败）会自动重试 2 次（间隔 1.5s）。
- **忽略表**：`MEMO_IGNORE`（`.env`）的规则指令删不掉，只有 `ignore.json` 里的能被「忽略 删除」/「忽略 清空」改；规则长度下限 2 字。
- 生产存储可把 `store.py` 换成任意数据库后端（接口不变）。

- `moyu-user.json` —— 你自己改过的那份摸鱼库（本机覆盖；内置的 `moyu-data.json` 仍随代码走）
- `*.log` / `bot.pid` —— 运行时产物
- `extensions/local/` —— **你的私有指令**（查运势 / 自检 / 资源点等），不进公开仓库

### 发版与「检查更新」

**版本号只有一处真源**：`memo-bot/VERSION`。`version.py` 的 `VERSION` 常量跟它一致（有测试盯着），  
`packaging/memo-bot.iss` 也**直接读那个文件** —— 所以安装包名字里的版本号不会跟代码脱节。

配置中心「⑩ 版本 → 检查更新」会去 jsdelivr 读远端的 `VERSION` 比一比。有新版本时页面会多出一个  
**「⬇ 下载 v<新版本>」按钮**（可点、可右键复制链接），旁边还有 Releases 页面兜底入口。

**下载链接怎么来的**（`version.py`）：

| 情况                                      | 链接                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| 默认                                      | `https://github.com/<repo>/releases/download/v<版本>/memo-bot-setup-v<版本>.exe` |
| 设了 `MEMO_DOWNLOAD_BASE=https://你的域名/dl` | `https://你的域名/dl/memo-bot-setup-v<版本>.exe`                                   |

所以想换成**自己的服务器 / 对象存储**，只改一个环境变量，不用动代码。

**发版三步**（版本号改完再打包）：

1. 改 `VERSION`（和 `version.py` 的 `VERSION`），提交推送；
2. `python packaging/_build_dist.py` → `ISCC.exe packaging\memo-bot.iss`，产物是 `packaging\output\memo-bot-setup-v<版本>.exe`；
3. 在 GitHub 建一个 **tag 为 `v<版本>` 的 Release**，把那个 exe **原样上传成资产**。

🔴 第 3 步的 tag 和文件名**必须**和 `version.py` 里的模板一致（`v{ver}` / `memo-bot-setup-v{ver}.exe`），  
否则用户点「⬇ 下载新版」会 404。测试里有一条护栏盯着 `.iss` 和 `version.py` 这两处不许写歪。

> 安装包放在 GitHub Releases 上，国内下载**可能慢或连不上**。介意的话就把 exe 传到自己的服务器 /  
> 对象存储，然后设 `MEMO_DOWNLOAD_BASE` 指过去 —— 文件名保持一致即可。
