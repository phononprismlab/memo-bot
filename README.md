# memo-bot · 群 / 私聊 备忘 + 发文件机器人

本地运行的 QQ 机器人，走 QQ 官方机器人（**WebSocket 收 / HTTP 发**），只需出网，**无需公网 IP / 公网回调**。  
**群聊与私聊共用同一套指令与识别逻辑。**

## 四步跑起来！

如果在本机跑：  
Windows：按 `Win + R` → 输入 `cmd` → 回车，打开「命令提示符」，把两行**一行一行**粘进去、每行按一次回车。  
Mac：打开「终端」App（在「启动台 → 其他」里），同样一行一行粘。  
👉 **完全不想碰命令行也行**：Windows 直接**双击**本目录里的 **`配置中心.bat`** —— 它会自己检查 Python、缺依赖自动装，然后打开配置页。

```bash
pip install -r requirements.txt
python config-web.py            # 起「配置中心」→ 浏览器自动打开一个配置页
```

1. 在配置中心填 **AppID / AppSecret**（在 [q.qq.com](https://q.qq.com) 创建机器人后，从「开发设置」拿）。
   - 🔴 **第一次点「复制」拿到 AppSecret 时，页面会提示密钥被重置 —— 这是正常的，不用担心。**
   - 但**复制到的那一串一定要自己存好**（记事本、密码管理器都行）。因为**关掉页面之后再想看，它还会再重置一次**，  
     之前那一串当场失效，机器人就连不上了。
2. 点页面底部 **「保存并重启机器人」**；
3. 把机器人拉进你的群，用手机点击群内机器人头像，右上角设置，打开这两个配置：
   1. **机器人可获取的群聊消息范围 = 获取群内全部消息** → 机器人能收到**非 @** 的群消息（`GROUP_MESSAGE_CREATE`）。
   2. **机器人主动在群聊内发言 = 开** → 机器人可**主动推送**（不再受 5 分钟被动窗口限制）。
   设置页长这样，照着找这两行就行 👇
   - **播报发给谁，你自己勾**：机器人见过哪些会话（群 / 私聊），配置中心「① 连接 QQ」页的**「播报目标」列表**里就列哪些。勾上 = 启动播报 / 关机播报也发到那里；群和私聊**平级**，想只收私聊就把群取消勾选。不用自己去翻 openid。
   - **每个会话还能起个名字**：QQ 不给机器人读群名 / 用户名（群名接口要白名单，私聊压根没接口），所以列表里默认显示的是一串 id。点「改名」自己起一个，旁边还有「最近说过什么 + 最后说话时间」帮你认。
   - **完全不想用群？也可以**：直接私聊机器人就能用（备忘 / 灵感 / 发文件 / 摸鱼 / 回旋镖全都在）。对方私聊过它之后就会出现在播报目标列表里，勾上就收得到播报。这条路不需要上面那两个群开关。
4. 群里发一条 `备忘 测试` 就有回执了。

其余配置——触发词、发文件的搜索目录、开机自启、忽略表——**都在配置中心那一页上**，不用碰 `.env`，也不用记命令。

## 能力

1. **备忘（我要做）**：群消息以触发词（默认「备忘」）开头 → 记为 `memo`，落本地 SQLite，并回执。  
   在[脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)页上**完成 / 取消完成 / 丢弃**。
2. **灵感（我的想法）**：群里**非 @** 的普通发言、以及**私聊里的任意非指令文本** → 自动收作 `idea`（**静默记录，不打扰**）。
3. **脑内抽屉**：一条命令起一个本地网页（`brain-drawer.py --serve`），把**备忘 + 灵感**放成不停往上飘的卡片，  
   **点一下直接写库** —— 备忘完成 / 丢弃、灵感改状态、写错的正文随时改（创建时间不变），不用导出任何文件（见 [脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)）。
4. **发**：把本地文件经机器人发送到指定**群 / 私聊**；文本类文件**渲染成图片**发送。
5. **上线播报 / 新手引导**：**第一次**连上时在群里发一段「功能介绍」（自我介绍，并写明**没有语言生成能力**），  
   之后每次启动只发一句「我上班了，开摸！」。两段文案都在配置中心里改（见 [配置](#配置三个入口)）。
6. **摸鱼**：发「摸鱼」→ 从内置库里随机抽一条放松动作 / 摸鱼点子，帮忙从工位上分神 30 秒。
7. **配置中心**：一条命令起一个本地网页（`config-web.py`），填凭据 / 选目录 / 开自启 / 启停机器人 / 看依赖，  
   **不用碰 `.env`、不用记命令**（见 [配置中心](#配置中心本地网页)）。
8. **设置**：`设置` / `设置 <键> <值>` —— 在群里也能改本机配置（关机通知文案、启动播报、脑内抽屉展示范围），  
   **与配置中心网页写同一份文件**。
9. **回旋镖**：发「回旋镖」→ 从「N 天以前」的旧记录里**随机翻一条推回来**，提醒你回头看当时的备忘 / 灵感（有结论的会连结论一起推）。  
   推过的打上标记**不再重复推**；回溯天数与「翻哪几类」都在配置中心里调。
10. **导出**：发「导出」→ 把**全部备忘 + 灵感**导成一个文件发回给你（md / txt / json，默认 md）；  
    脑内抽屉页顶部也有「⬇ 导出」按钮，点一下浏览器直接「另存为」—— 两边导出的排版一模一样。
11. **指令（群 / 私聊通用）**：

| 指令               | 作用                                                            | 群内是否需 @ |
| ---------------- | ------------------------------------------------------------- | ------- |
| `备忘 <内容>`        | 记一条备忘                                                         | 否       |
| `查备忘`            | 看最近 10 条备忘                                                    | 否       |
| `查灵感`            | 看**还没处理**的灵感（含待处理/已处理/已决议/已丢弃计数）                              | 否       |
| `发文件 <关键词>`      | 搜**配置的根目录**（默认你的用户主目录，可在配置中心改）的文件、渲染成图片发送；命中多个列出来让你回复序号选      | 否       |
| `摸鱼`（可加条数 / 分类）  | 随机来一条**放松动作 / 摸鱼点子**，歇一下                                      | 否       |
| `回旋镖`（可加天数）      | 从 N 天前（默认 3 天）的旧记录里翻一条推回来                                     | 否       |
| `导出`（可加格式）       | 把全部备忘 + 灵感导成文件发回来（`导出 json` / `导出 txt`）                       | 否       |
| `忽略 <内容>`        | 含该内容的消息**一律跳过**（不收灵感、不响应）；`忽略 列表` / `忽略 删除 <内容>` / `忽略 清空` 管理 | 否       |
| `设置 [<键> [<值>]]` | 看 / 改本机设置；`设置 重置 <键>` 恢复默认                                    | 否       |
| `你好`             | 回一段自我介绍（**和首次上线发的那段「功能介绍」是同一份设置**）                            | 否       |
| `帮助`             | 显示指令菜单                                                        | 否       |

- 🔴 **`你好` 回的就是设置里的「功能介绍」** —— 那段文案里对外说清了「**我没有语言生成能力**」：不会聊天、不会回答问题、不会替你写东西。  
  改一次，**首次上线播报**与**「你好」回复**一起变；把这项留空，「你好」会回一段内置短文案（同样写明没有语言生成能力），不会变成「没反应」。
- 🔴 **功能介绍只在第一次连上时发一次**：发成功后在**数据目录**写一个 `onboarded.json` 标记；之后每次启动只发「启动播报」。  
  一个群都没发成功（网络 / 权限问题）→ 不写标记，下次启动重试。

- **@机器人**时可简写（`发 设计说明`、`发送 xxx`）；**私聊**里不需要 @，同样按宽松写法识别。
- **群里不 @** 时只认明确写法（`发文件` / `找文件` / `发送文件`），避免「发工资了吗」这类误触。
- 「发文件」支持模糊匹配（如「设计说明」能命中「设计风格参考说明-2026-10-08.md」），回复**序号**或**文件名片段**即可选定。
- 🔴 **命中多个时的列表顺序 = 匹配分降序 → 同分时修改时间倒序（最新在前）→ 再同分时路径短的在前**。  
  所以「最相关的排最前」优先于「最新的排最前」：模糊查询的最佳命中不会被一堆无关的新文件压下去。
- 以上是**内置指令**。想加自己的指令（天气、运势、系统状态…）→ 见 [可扩展性](#可扩展性加你自己的指令)：  
  自定义指令放 `extensions/local/`，**不会进公开仓库**。

### 忽略表：别把别的机器人当内容收

两个机器人待在一个群里时会**互相把对方说的话收作灵感**，极端情况下还会形成互相响应的循环。  
把对方的昵称 / openid 记进忽略表即可打断，实现见 `ignore.py`。

- **两种规则语义**，命中任一即跳过整条消息（不收灵感、不回复）：
  1. **子串** —— 消息文本（剥掉 @ 标记后）含该串即命中，**忽略大小写**；
  2. **发送者** —— 发送者 id 与该串**完全相等**即命中。
- **两个来源**（都生效，`忽略 列表` 会标注来源）：
  - `MEMO_IGNORE`（`.env`，逗号分隔）—— 改 `.env` 即生效，**指令删不掉**（防误删把循环放出来）；
  - `ignore.json`（同目录，可用 `MEMO_IGNORE_FILE` 改路径）—— 由「忽略」指令维护。
- 「忽略」指令本身**永远放行**（否则会被自己的规则吃掉）；`忽略这个bug` 这类没分隔符的普通聊天**不算指令**。
- 规则长度下限 2 字（太短会误伤一大片，直接拒绝）。

## 配置中心（本地网页）

以前改配置只能动 `memo-bot/.env`：要开编辑器、要记住变量名、还得重启 bot。现在有一条命令：

```bash
python config-web.py            # 起服务并自动打开浏览器
python config-web.py --port 8770 --no-browser
```

> **Windows 用户**：直接双击 `配置中心.bat` 也行（装好 Python 就可以，不用敲命令）。

页面上能做这些事，**每一项都有中文说明，填错会告诉你错在哪**：

| 分区      | 能改什么                                                | 写去哪                      |
| ------- | --------------------------------------------------- | ------------------------ |
| ① 连接 QQ | AppID / AppSecret / 沙箱开关；中间有**「去 QQ 里开两个开关」提醒块（带 QQ 设置页截图）**；下面一张**「播报目标」列表** —— 机器人见过的会话（群 + 私聊）都在里面，勾选决定启动 / 关机播报发到哪，每个还能**改名**（旁边带「最近说过什么 + 最后说话时间」） | `.env`                   |
| ② 群内行为  | 备忘触发词、**备忘回执**、**灵感回执**                              | `.env` / `settings.json` |
| ③ 播报文案  | 启动播报、关机通知文案、**功能介绍**（首次上线自动发的那段；发「你好」也回它）            | `settings.json`          |
| ④ 发文件   | 「发文件」的搜索根目录（**可填多个，一行一个**；带**目录浏览器** + **实测按钮**：这些目录一共多少文件、扫一遍要多久） | `.env`                   |
| ⑤ 脑内抽屉  | 内容流放哪几类（备忘 / 灵感）                                    | `settings.json`          |
| ⑥ 回旋镖   | 回溯天数（默认 3 天）+ 推送范围（备忘 / 待处理 / 已处理 / 已决议 / 已丢弃）      | `settings.json`          |
| ⑦ 运行方式  | **开机自启开关**、**启动 / 停止 / 重启机器人**、**依赖自检**、**数据文件位置（一键打开所在文件夹）**、**版本 + 检查更新 + ⬇ 下载新版** | 计划任务 / 进程                |
| ⑧ 忽略表   | 忽略关键词 + 规则列表（可增删）                                   | `.env` / `ignore.json`   |
| ⑨ 摸鱼库   | 「摸鱼」随机抽的那些内容，**一行一条**，三类分开改（放松 / 摸鱼 / 冷知识）；有实时条数、**恢复内置默认**、**打开库文件位置** | `moyu-user.json`         |

🔴 **一次只显示一块**：上面这些分区是**页签**，切一个看一块，不用一路往下拉。
**凭据没填全时页签条不出现**，页面上只留「① 连接 QQ」—— 填好 AppID / AppSecret 保存后，其余页签才出来。

🔴 **「① 连接 QQ」页里有一块「去 QQ 里开两个开关」的提醒**（群聊消息范围 = 获取群内全部消息、机器人主动在群聊内发言 = 开）。
这两项**在 QQ 那边管，配置中心改不了**，但不开的话机器人收不到群里的普通发言、也发不出播报，用户会以为「机器人坏了」——
所以直接摆在连接页上，不指望人家去翻安装指南。提醒块放在「播报目标」列表**上面**：一个会话都没发现时，
用户第一眼就能看到「是不是这两个开关没开」。

改摸鱼库**不用重启机器人**：保存完下次发「摸鱼」就是新的。改凭据 / 触发词 / 搜索根才要重启。

页面顶部常驻状态：机器人是否在跑（含 pid）、开机自启是否已开。凭据没填全时会有一条醒目提示。

### 🔴 三条硬规则

- **只监听 `127.0.0.1`** —— 这个页面能读写 `.env`（含密钥），绝不对外暴露。
- **AppSecret 不回显** —— 已保存的密钥只显示「已设置 ✓」，留空 = 不改；要换就重新填一遍。
- **写 `.env` 是按行改** —— 你手写的注释与顺序原样保留，已有键只换值，新键追加到末尾；  
  写前自动备份成 `.env.bak`（已 gitignore）。路径里的反斜杠会自动转成正斜杠。

所有写操作都要求自定义请求头 `X-Memo-Config: 1` —— 别的网页跨域打过来会先触发 preflight，  
而我们不回任何 CORS 头，浏览器直接拒发，等于天然的 CSRF 防护。

> 改完**凭据 / 触发词 / 搜索目录**要重启机器人才生效 —— 页面上直接有「保存并重启机器人」按钮。  
> 改**文案 / 展示范围**同样建议重启（文案是 bot 启动时读的）。

## 配置：三个入口

`settings.json` 是「非敏感的行为配置」，三个入口改的都是它：

| 入口        | 怎么用                                          | 放哪些                   |
| --------- | -------------------------------------------- | --------------------- |
| **配置中心**  | `python config-web.py` → 网页上填                | 全部（含 `.env` 里的凭据与路径）  |
| **脑内抽屉页** | 页面顶部「⚙ 设置」                                   | 只有「内容流放哪几类」（跟当前页面强相关） |
| **机器人**   | `设置` 看全部 · `设置 <键> <值>` 改 · `设置 重置 <键>` 恢复默认 | `settings.json` 里的八个键 |

- **取值优先级**：`settings.json` → 同名环境变量（`.env`）→ 内置默认值。  
  只把**显式改过**的键写进文件，所以老配置（`.env` 里的 `QQ_STARTUP_MSG` / `OFFWORK_MSG`）不会失效，继续当回退值。
- 🔴 **密钥不进 `settings.json`** —— AppID / AppSecret / 群 openid 仍留在 `.env`。  
  这个文件的内容会经网页和群消息来回传，不放秘密。
- 🔴 **`settings.json` 已 gitignore**（含本机文案 / 群内信息）。

`settings.json` 里的键：

| 键                 | 中文名      | 类型   | 默认值                           |
| ----------------- | -------- | ---- | ----------------------------- |
| `startup_msg`     | 启动播报     | 文本   | `我上班了，开摸！`（留空 = 不播报）          |
| `offwork_msg`     | 关机通知文案   | 文本   | `现在开始，我要下班了！`（留空 = 不发）        |
| `intro_msg`       | 功能介绍     | 多行文本 | 一段自我介绍，**写明「没有语言生成能力」**；首次上线自动发、「你好」也回它 |
| `memo_ack`        | 备忘回执     | 文本   | `已经放进脑内抽屉了`（留空 = 静默记下）        |
| `idea_ack`        | 灵感回执     | 文本   | 空 = 静默收下。填一句就回，例如 `💡 已收作灵感`    |
| `bubbles_show`    | 脑内抽屉展示范围 | 多选   | 备忘 + 待处理                      |
| `boomerang_days`  | 回旋镖回溯天数  | 整数   | `3`（1 ~ 365；刚记的还不算）           |
| `boomerang_scope` | 回旋镖推送范围  | 多选   | 备忘 + 待处理 + 已处理 + 已决议（不含「已丢弃」） |

> 配置中心的分区顺序、`设置` 指令列出的顺序，都按上表排。

- 文本类：直接写值；`设置 重置 <键>` 从文件里删掉该键 → 回到 env / 默认值。
- 多选类：值可写 code 或**中文标签**（`设置 bubbles_show 待处理,已处理`），认不出会拒绝并列出可选项。
- 整数类：只收整数，超范围会被拒绝并告诉你上下限（`设置 boomerang_days 7`）。
- 指令词后面**必须有分隔符**（空格 / `：` / `:`）—— 否则「设置好了」「配置一下」这种普通聊天会被误判成指令（这类消息照常当灵感收下）。
- 网页侧是**批量提交、先全量校验再一次性落盘**：改 5 项、第 3 项填错 → 整批不写，不会留半成品。  
  且**只提交改动过的键** —— 只动展示范围就不会顺手把两个文案键也写进文件（`.env` 的回退一直有效）；什么都没改会提示「没有改动」并跳过请求。
- HTTP 接口（两个网页服务各自提供）：`GET /api/settings`（读全部键与选项）· `POST /api/settings`（批量写；有非法值返 `400` + 中文原因）。

> 关机自动发「下班了」的文案就是 `offwork_msg` —— 配置中心改、群里改、留空关掉，都不需要碰代码或 `.env`。

## 私聊（单聊）支持

群与私聊走**同一套指令与识别逻辑**，私聊里不需要 @。

- **平台侧要开**：QQ 开放平台 → 开发设置 → 功能配置，开启「单聊」能力（沙箱与正式环境各自配置）；用户需先与机器人建立单聊会话。
- **私聊里的行为**：
  - 内置指令（`备忘` / `查备忘` / `查灵感` / `发文件` / `摸鱼` / `回旋镖` / `导出` / `忽略` / `帮助`）与扩展指令都可用；`发文件` 用宽松别名（`发 设计说明` 也行）。
  - **非指令文本**一律静默收作「灵感」（私聊没有「打扰群」的顾虑）。想要回执，在**配置中心 → ② 群内行为 → 灵感回执**里填一句（例如「💡 已收作灵感」）；留空就是静默收下。
  - 私聊里发文件 / 发图走**被动回复**（带触发消息的 `msg_id`）—— 用户刚发来一条指令，回给「那条消息」语义更准，也不占主动消息额度。
- **存储**：私聊记录落同一张 `memos` 表，`group_id` = `c2c:<user_openid>`、`group_name` = `私聊`，与群记录互不干扰。
- **技术**：`C2C_MESSAGE_CREATE` 由 botpy 1.2.1 **原生解析**（无需像群全量消息那样补解析器）；intents 仍是 `public_messages=True`（它同时覆盖群与 C2C）。
- **命令行发私聊**：`python send_file.py --file <路径> --user <user_openid>`（单聊无主动权限，自动走被动回复）。

### 几个文件的内部要点

- `bot.py`
  - 路由主体是**模块级** `route_message(client, message, mentioned, scope)`（不在 `main()` 内的类里），便于回归测试直接驱动；`MemoClient.route()` 只是转发。
  - 运行时用 `install_group_message_parser()` 给 botpy 补上 `GROUP_MESSAGE_CREATE` 解析器（官方 1.2.1 未注册该事件，会被网关丢弃）；`C2C_MESSAGE_CREATE` 官方已注册，无需补。
  - `--log <文件>` 把 stdout/stderr 与 logging 重定向到文件，供 `pythonw.exe` 无控制台常驻运行。
- `send_file.py`：群 / 单聊由 `scope` 切换（`--group` / `--user`）；**默认主动推送**（群需开启「机器人主动发言」；单聊无需开关，实测可主动推送），群内主动失败会自动降级被动回复，`--passive` 可强制被动。上传带 `file_name`（否则 QQ 文件卡片显示「未命名」），并对 `305013`（审核服务超时）/ `850027`（发送超时）/ `40093001`（上传失败）**自动重试 2 次**。
- `config-web.py`：`ENV_SPEC` 是**白名单** —— 页面只能改表里列出的键；写 `.env` 按行改（注释与顺序保留）；`_powershell()` 强制 UTF-8 输出且 `ErrorActionPreference='Stop'`（否则注册计划任务失败会被误报成成功）。
- `brain-drawer.py`：内容流放哪几类由设置 `bubbles_show` 决定（默认「备忘 + 待处理」）；顶部「⚙ 设置」只放这一项。  
  `--serve` 起本地服务后页面上直接写库（桌面入口走这条）；不带参数则只生成静态快照 `脑内抽屉.html`。  
  **备忘和灵感混在一条流里**，每条带一个「桶」（`memo` / `memo_done` / `open` / `done` / `decided` / `dropped`），  
  分流 / 配色 / 计数全按桶走；备忘三态（`store.set_memo_status`）走 `POST /api/memo`。  
  🔴 **「已丢弃」是两类共用的桶**；永久删除（`store.delete_items`）走 `POST /api/delete`，**只在页面上确认着点**，不进 `--apply`。  
  ✏️ **每条都能改正文**（`store.update_content`）走 `POST /api/edit` —— **创建时间不变**，改错了再改回来，所以它**进** `--apply`。

## 发送格式：文本类文件渲染成图片

**手机端文件卡片常打不开**（尤其 `.md` 这类无默认应用的类型），而把内容拆成多条文本消息又太碎。因此：

| 文件类型                                                         | 发送方式                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 文本类（`.md/.txt/.json/.py/.js/.csv/.log/.html/.yml` 等）且 ≤150KB | **渲染成图片发送**（Markdown 转 HTML → Chrome 截图 → `file_type=1`），手机端原生可看、可缩放、保留排版 |
| 图片 / 视频 / 语音                                                 | 对应富媒体（手机原生可看）                                                             |
| 其他二进制 / 超大文本                                                 | 文件卡片（`file_type=4`）                                                       |

- 渲染链路：`md2img.py`（Python `markdown` 库 → HTML）→ `md2png.mjs`（Node + `playwright-core` 用系统 Chrome 截图）。
- 默认**单张长图**（宽 760 CSS px、dpr=2）；整篇超过 14000 CSS px 才自动分页。
- 🔴 **正文里的相对路径图片**靠注入 `<base href="{源文件目录}/">` 加载（HTML 写在临时目录，否则图片全部不显示）；正文图片限高 600px。
- CLI：`--as-text` 强制文本直发、`--as-file` 强制文件卡片。
- 🔴 被动回复的 `msg_seq` 在 bot（1~3）与 CLI（从 100 起）之间**必须错开**，否则同一 `msg_id` 会撞 `40054005 消息被去重`。

## 备忘 vs 灵感

**一句话区分：备忘 = 我要做，灵感 = 我的想法。**

|    | 是什么      | 触发                         | 落库 `kind` | 处理方式                                                       | 是否回执         |
| -- | -------- | -------------------------- | --------- | ---------------------------------------------------------- | ------------ |
| 备忘 | **我要做**  | `@bot 备忘 xxx`，或任意位置以「备忘」开头 | `memo`    | 三态：**没完成 / 已完成 / 已丢弃**（在[脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)页上点勾选框或丢弃） | 回「已记到秘书会话 ✅」 |
| 灵感 | **我的想法** | 群里**非 @** 的普通发言            | `idea`    | 四态：待处理 / 已处理 / 已决议 / 已丢弃                                   | **不回执**（静默）  |

- **备忘的 `status` 有三态**：`open`（没完成）/ `done`（已完成）/ `dropped`（已丢弃），改状态时间记在 `processed_at`。
  🔴 备忘**没有 `decided`** —— 它是「我要做」，要么做完，要么不做了。
- 🔴 **「已丢弃」是两类共用的桶**：丢弃的备忘和丢弃的灵感都进同一个列表，列表里可以「← 恢复」或「🗑 永久删除」。
- ✏️ **两类都能「再次编辑」正文**：回顾时发现写错字、或对某件事有了新想法，随时改 —— **创建时间不变**（时间轴不会乱）。
- **灵感的 `status` 有四态**：

| 状态        | 含义              | 导出标记  |
| --------- | --------------- | ----- |
| `open`    | 待处理             | `[ ]` |
| `done`    | 已处理（产生了行动并完成）   | `[x]` |
| `decided` | 已决议（有结论，但不产生行动） | `[~]` |
| `dropped` | 已丢弃（不成立 / 无效）   | `[-]` |

- 两者都存在同一张 `memos` 表里、同一个[脑内抽屉](#脑内抽屉把我要做和我的想法放成一个轮播页面实时处理端)页面上，  
  靠「桶」（`memo` / `memo_done` / `open` / `done` / `decided` / `dropped`）分流。

`查备忘` / `查灵感` 分别只看对应类别（`查灵感` 只列 `open`）；`python bot.py --list` 打印全部并标注类别。

## 灵感池：给「专门处理灵感的会话」用的入口

灵感是碎片，需要在电脑上集中处理（评估 → 做/不做 → 留结论）。`ideas.py` 提供这个闭环：

```bash
python memo-bot/ideas.py --export              # 导出「待处理」灵感 → 工作区 灵感池.md（逐条编号）
python memo-bot/ideas.py --list                # 终端列出待处理（--all 看全部）
python memo-bot/ideas.py --done 1,3 --note "已做成 X"   # 标记处理完（有行动）
python memo-bot/ideas.py --decide 4 --note "结论：不做 X"  # 标记已决议（有结论、无行动）
python memo-bot/ideas.py --drop 2 --note "与现有方案重复"  # 标记丢弃
python memo-bot/ideas.py --stats               # 只看计数
```

- **序号**（`1,2,3…`）相对**当前待处理列表**，每次 `--export` 后固定；也支持传 id 前 8 位。
- 处理过的灵感从「待处理」消失、进 `灵感池.md` 的归档区，**不会被重复捞**。
- 存储字段：`status`（open/done/decided/dropped）+ `note`（结论）+ `processed_at`（处理时间）。

> 新会话开场直接说「处理灵感」即可 —— 项目记忆里已登记这条入口。

## 摸鱼库：群内发「摸鱼」随机歇一下

内容全部是**本地静态库**（内置 65 条），不调 AI、不联网、零延迟。

| 指令                  | 结果                             |
| ------------------- | ------------------------------ |
| `摸鱼` / `放松` / `歇会儿` | 抽 1 条（**默认池 = 放松 + 摸鱼，不含冷知识**） |
| `摸鱼 3` / `摸鱼 3 条`   | 一次抽 3 条（上限 5 条）                |
| `摸鱼 冷知识`            | 只抽冷知识                          |
| `摸鱼 3 冷知识`          | 条数与分类可组合                       |
| `摸鱼 全部`             | 三类混抽                           |

### 改内容：两份库，一份种子一份你的

| 文件                  | 是什么                | 谁写它                |
| ------------------- | ------------------ | ------------------ |
| `moyu-data.json`    | **内置库（只读种子）**，随代码走 | 只读。程序**永远不写它**     |
| `moyu-user.json`    | **你自己那份**，落在数据目录   | 配置中心「⑨ 摸鱼库」页签保存时写 |

- **生效规则**：数据目录里有 `moyu-user.json` 就用它，没有就用内置库。
- **怎么改**（三种，改的都是同一份）：配置中心「⑨ 摸鱼库」页签（推荐）、直接编辑 `moyu-user.json`、删掉 `moyu-user.json` = 恢复内置。
- 🔴 内置库只当种子。源码版的数据目录就是代码目录，所以**不能**直接往 `moyu-data.json` 写，否则会把跟着版本走的库覆盖掉。
- 用户库读坏了 / 是空的 → **悄悄退回内置库**，不会让「摸鱼」整个哑掉。
- 改完库会**清空**「最近抽过哪些」的记录（`id` 是位置编号，换内容后含义就变了）。

### 🔴 指令识别是「宽容」的，不是精确匹配

群里没人会规规矩矩打「摸鱼」两个字。识别走 **归一化 → 前缀匹配 → 参数解析** 三步：

| 你打的                 | 归一化后         | 结果             |
| ------------------- | ------------ | -------------- |
| `摸鱼！` `摸鱼~` `摸鱼。`   | `摸鱼`         | ✅              |
| `摸摸鱼`               | `摸鱼`（重复字压缩）  | ✅              |
| `想摸鱼` `来点摸鱼` `该摸鱼了` | `摸鱼`（剥前置语气词） | ✅              |
| `摸鱼吗` `摸鱼吧` `摸鱼一下`  | `摸鱼`（剥后置语气词） | ✅              |
| `摸个鱼`               | 同义词表         | ✅              |
| `摸鱼 3 条`            | `摸鱼3条`       | ✅ 抽 3 条        |
| `今天不想摸鱼了`           | —            | ❌ 不是指令（句中，不触发） |

- **@ 机器人**时若参数不认识（如 `摸鱼 来点啥`），回一句参数提示；  
  **非 @** 时不打扰群聊，按普通发言处理。
- **防重复**：最近抽过的 20 条记在 `moyu-recent.json`，抽的时候排除；某个池快抽完一轮就重置。
- 保存时校验：三类不能全空、单条最长 120 字、每类最多 200 条（防手滑粘进来一整本书）。
- CLI：`python moyu.py` / `python moyu.py 3` / `python moyu.py --cat trivia` / `python moyu.py --parse "摸鱼！"` / `python moyu.py --stats`。

## 回旋镖：把旧账翻回来

记下来的东西容易沉底。发一条「回旋镖」，机器人就从**N 天以前**的记录里随机挑一条推回给你。

| 指令      | 结果                   |
| ------- | -------------------- |
| `回旋镖`   | 用配置里的回溯天数（默认 3 天）翻一条 |
| `回旋镖 7` | 只看 7 天以前的            |
| `回旋镖 0` | 今天记的也翻 —— **刚上手第一发就有反应** |
| `回旋标`   | 别名，一样能用              |

- **哪发的指令就推回哪**：群里发就回群里，私聊发就回私聊。
- **推过的不再推**：每条记录推一次就打上时间戳，下回换别的；同一批推完会告诉你「都推过一遍了」。  
  新记的内容满天数后会自动进池子。
- 🔴 **回溯天数可以填 0**（配置中心「⑥ 回旋镖」里改，或 `设置 boomerang_days 0`）：填 0 就是
  **今天记的也算**，刚试用的用户发一句「回旋镖」立刻能看到效果，不会被「还没满 3 天」挡在门外。
- **推哪几类、往前翻几天**：在配置中心「⑥ 回旋镖」里调（也能用 `设置 boomerang_days 7` /  
  `设置 boomerang_scope 备忘,已决议`）。默认覆盖备忘 + 待处理 + 已处理 + 已决议，**不含「已丢弃」**。
- 挑中的是**灵感**且当时留了结论时，会把「【当时的结论】…」一并推给你。

## 导出：把全部备忘 + 灵感装进一个文件

发「导出」→ 机器人把库里所有备忘和灵感排成一个文件发回来。

| 指令             | 结果                                                 |
| -------------- | -------------------------------------------------- |
| `导出` / `导出 md` | Markdown（默认）：正文放引用块，换行原样保留                         |
| `导出 txt`       | 纯文本，按类别分节                                          |
| `导出 json`      | 结构化，带 `exported_at` / `counts` / `memos` / `ideas` |

- 灵感按**状态分组**（待处理 / 已处理 / 已决议 / 已丢弃）排列，有结论的连结论一起带上。
- **脑内抽屉页顶部也有「⬇ 导出」按钮**（在线模式才出现），点一下浏览器直接「另存为」。  
  群指令和页面按钮走的是 `export.py` 里**同一套排版**，导出来长得一模一样。
- 发出去的是**文件卡片本身**，不会被渲染成图片 —— 方便你直接存下来或丢进别的工具。

## 脑内抽屉：把「我要做」和「我的想法」放成一个轮播页面（实时处理端）

`brain-drawer.py` 读 `memos.db`，把**备忘 + 灵感**渲染成不停往上飘的卡片轮播页。

> **为什么叫「抽屉」**：这个页面装两类东西 ——  
> **备忘 = 我要做**（没完成 / 已完成 / 已丢弃，卡片左上角一个勾选框）；  
> **灵感 = 我的想法**（有 待处理 / 已处理 / 已决议 / 已丢弃 四态）。  
> 以前备忘只有群指令、没有界面，处理链路是断的；现在补上了。

```bash
python memo-bot/brain-drawer.py --serve      # 【推荐】起本地服务 + 打开浏览器：点一下直接写库
python memo-bot/brain-drawer.py              # 只生成静态 HTML → 工作区根目录 脑内抽屉.html
python memo-bot/brain-drawer.py --open-only  # 只带「没完成的备忘 + 待处理灵感」
python memo-bot/brain-drawer.py --no-memo    # 不带备忘，只看灵感
python memo-bot/brain-drawer.py --apply 抽屉操作.json   # 应用离线模式导出的操作
```

### 第一次打开：会有几条示例，不会是一片空白

库**第一次建出来**的时候（不管先跑的是机器人还是这个页面），会自动放 **4 条示例**：

| 类型 | 内容大意 |
| --- | --- |
| 灵感 ×3 | 群里随手发一句就收成灵感（不用 @）/ 点卡片就能处理 / 发「回旋镖」把旧记录翻回来 |
| 备忘 ×1 | 在群里发「摸鱼」，随机回你一条摸鱼文案 |

- 它们就是**普通记录** —— 能编辑、能完成、能丢弃、能永久删除，跟你自己记的没有任何区别。看懂了随手点掉就行。
- 🔴 **只在库是全新的时候塞一次**：判据是 `memos` 表此前**不存在**（不是「表是空的」）。
  所以老库绝不动，示例被你删光/处理光之后也**不会**又给你塞回来。
- 想要一个干净的库：设 `MEMO_NO_SEED=1`（见 `.env.example`）。

### 视图：内容流放哪几类由设置决定

- **默认放「备忘 + 待处理」**。已完成的备忘 / 已处理 / 已决议 / 已丢弃**默认不进流**，去各自的列表里看。  
  想同时看到别的类别 → 顶部「⚙ 设置」勾选（或配置中心网页、或群里发 `设置 bubbles_show 备忘,待处理`），存完内容流立刻重建。  
  展示范围以服务端为准：**刷新页面会重新拉一次**，所以别人（或机器人指令）改过之后刷新就能看到。
- 顶部四个按钮：**`✓ 已完成 N` / `✅ 已处理 N` / `📌 已决议 N` / `🗑 垃圾桶 N`**，点开是一个列表浮层：  
  每条显示时间 + 全文 + 结论，右侧一个按钮把它放回内容流（备忘是「← 取消完成」，灵感是「← 恢复」）。
- **完成 ≠ 删除、丢弃 ≠ 删除**：记录仍在 `memos.db`（`status=done` / `dropped`），只是换个桶，随时可恢复。
- 点列表里的某一条 → 打开详情浮层。灵感可以改成任意状态（含填结论）；备忘有「完成 / 取消完成 / 丢弃 / 恢复」。
- ✏️ **每条右侧还有个「✏️ 编辑」** —— 点它就打开详情浮层、并直接进编辑态（见下节）。
- 🔴 **「垃圾桶」是两类共用的** —— 丢弃的备忘和丢弃的灵感都在里面，所以它是唯一能**永久删除**的地方。

### ✏️ 再次编辑正文：改内容，不改时间

回顾的时候发现写错了字、或者对某件事有了新想法 —— 改正文就行，不用删了重记。

- **两个入口**：详情浮层右上角的「✏️ 编辑」；归档列表里每行右侧的「✏️ 编辑」（点它会关掉列表、直接进编辑态）。
- 点开后正文变成一个文本框，预填当前内容，底下是「取消 / 保存」，旁边写着**创建时间不变**。
- 🔴 **只改正文，创建时间（`created_at`）一个字节都不动** —— 时间轴不会乱、排序也不会跳。
  数据层 `store.update_content()` 的 SQL 里**根本没带 `created_at`**（有回归测试锁死这一点）。
- 🔴 **编辑态下空格是打字，不是暂停轮播**；**Esc 先退出编辑**（再按一次才关浮层）。
- 备忘和灵感**都能改**，已丢弃的也能改（改完还是留在垃圾桶里）。
- 编辑是**可逆**的（改错了再改回来），所以它和改状态一样**进** `--apply`；离线模式下会记进待提交，导出后一样能落地。

### 永久删除：页面上唯一会真删数据的操作

「🗑 垃圾桶」列表里每条右侧有「🗑 永久删除」。点它会先弹一个确认框：

- 框里写明**从库里抹掉、找不回来**，并把要删的那条原文贴出来给你确认。
- 底下有个「**以后不再提示**」勾选框：勾上之后，下次点「永久删除」**直接删、不再问**。
- 这个偏好存在**浏览器本地**（`localStorage`），不进 `settings.json` —— 它是这台机器上这个浏览器的习惯，不是机器人的配置。  
  想让它重新弹出来：顶部「⚙ 设置」里的「**永久删除前再确认**」勾回去。
- 🔴 **离线模式（`file://` 双击 HTML）不给删** —— 按钮置灰。这一下不可恢复，不该跟着「导出操作文件 → `--apply`」  
  那条可以反复执行的链路走（文件可以重复应用，误删没法挽回）。`--apply` 也不接受删除操作。

### 备忘的勾选框

- 备忘卡片左上角有个方框，**点一下标记完成**（框里出现对勾、卡片挪进「✓ 已完成」列表），再点一下取消。
- 勾选框是 **CSS 画的**（方框 + 旋转 45° 的伪元素当对勾），不依赖 `☐` / `☑` 字符 —— 那些字符在部分系统上会缺字形。
- 点勾选框**不会**打开详情浮层（事件已拦），点卡片其他地方才打开。

### 实时：页内处理直接写库

- **`--serve` 直连模式（推荐）**：点按钮**直接 POST 写 `memos.db`**，不需要导出任何文件。  
  另外每 20 秒拉一次 `/api/items` —— **群里 bot 新收的灵感会自动进流**。  
  页面顶部「⏻ 停止服务」可停（也可 Ctrl+C）。
- **离线（直接双击 HTML）**：操作暂存浏览器 localStorage，顶部显示「待提交 N 条」，  
  点它导出 `抽屉操作.json`，再跑 `--apply` 落地 —— **仅作降级**（静态页是快照，数据不会自己更新）。
- 悬停暂停单个气泡；**空格**暂停/继续生成；**Esc** 关浮层（编辑态先退出编辑，再按一次才关；详情浮层与设置浮层都关）。
- 🔴 **同一条记录同时最多一个卡片**：取条目时会跳过「已经在屏幕上的」，条目数比最大卡片数（宽屏 8 / 窄屏 5）少时不会把同一条重复铺开。开局按**实际条目数**均分飞行进度（不按最大卡片数），条目少也不会全挤在底部。
- 🔴 **有结论的条目会把结论一起显示**：卡片里正文下方用虚线隔开一段「结论：…」（已处理 / 已决议 / 已丢弃 通常带结论）。**没有结论就不显示**，和以前完全一样。结论算进了卡片高度估算，长文本判据也带上它，不会因为多了一段就撞上邻居。
- 🔴 **换行原样保留**：群里分几行写的记录，卡片和详情浮层里就是几行（容器 `white-space: pre-wrap`，  
  `clean()` 只压空格 / 制表符、**不压 `\n`**）。连续空行最多留一个；卡片高度与「长文本」判据都按  
  **显式换行 + 宽度折行**逐段算，不会因为多几行就撞上邻居。
- 防重叠布局：所有卡片同一下降速度 + 补位卡最小间隔 ⇒ 竖直永久等距；长文本按**估算高度**（非固定字数）决定是否横跨舞台。桌面 3 泳道 / 窄屏 2 泳道，边界泳道只向内漂。
- HTTP 接口：`GET /api/ping`（探活）· `GET /api/items`（全部备忘 + 灵感；`/api/ideas` 是旧别名）· `POST /api/status`（灵感改状态）· `POST /api/memo`（备忘改状态：完成 / 取消完成 / 丢弃）· `POST /api/edit`（**改正文，创建时间不变**）· `POST /api/delete`（**永久删除**一条，不可恢复）· `GET|POST /api/settings`（读 / 写设置）· `GET /api/export?format=md|txt|json`（下载导出文件）· `POST /api/quit`（停服务）。
- 顶部「**⬇ 导出**」按钮只在线模式下出现 —— 点一下走服务端 `/api/export`，浏览器直接「另存为」，  
  和群里发「导出」拿到的是**同一套排版**（排版只在 `export.py` 里定义一处）。

> 桌面快捷方式「脑内抽屉」走的就是 `--serve`：探测到服务没跑就用 `pythonw` 后台起一个（无窗口），  
> 已在跑就复用，然后开浏览器 —— 所以双击永远是**实时**的，不是快照。

## 配置项一览（全部走环境变量，见 `.env.example`）

所有敏感值与本机专属路径都通过环境变量注入，**代码里不写死任何本机路径**。以下变量都可选，不填走安全默认值。

### 必填（QQ 机器人凭据）

| 变量                | 说明                                                |
| ----------------- | ------------------------------------------------- |
| `QQ_BOT_APPID`    | QQ 机器人 AppID（<https://q.qq.com> 创建获取）             |
| `QQ_BOT_SECRET`   | AppSecret（**机器人密钥**，不是 Token）；兼容旧名 `QQ_BOT_TOKEN` |
| `QQ_PUSH_TARGETS` | 启动播报 / 关机播报发到哪些**会话**，格式 `group:<群openid>;c2c:<用户openid>`，可多个。🔴 **不用自己找** —— 配置中心「① 连接 QQ」页的「播报目标」列表里勾选就写进来了 |
| `QQ_GROUP_OPENID` | 旧版遗留键（可删）。仅当 `QQ_PUSH_TARGETS` **没配**时才回退使用 —— 老用户升级不丢配置 |
| `QQ_C2C_OPENID`   | 同上，旧版遗留的私聊目标键 |

### 可选（行为 / 路径）

| 变量                    | 默认值             | 说明                                                                                                              |
| --------------------- | --------------- | --------------------------------------------------------------------------------------------------------------- |
| `QQ_BOT_SANDBOX`      | `false`         | 是否走沙箱域名（本地联调设 `true`）                                                                                           |
| `MEMO_TRIGGER`        | `备忘`            | 备忘触发词                                                                                                           |
| `QQ_STARTUP_MSG`      | `我上班了，开摸！`      | 启动播报文案（留空不播报）。**建议改用配置中心网页、或 `设置 startup_msg <值>`**（写进 `settings.json`，优先级更高）                                   |
| `OFFWORK_MSG`         | `现在开始，我要下班了！`   | 关机自动播报文案（留空不发）。**建议改用配置中心网页、或 `设置 offwork_msg <值>`**                                                            |
| `MEMO_SEARCH_ROOT`    | 你的用户主目录 `~`     | 「发文件」搜索根；**不要指向含凭据的目录**（`.ssh`/`.aws`/`.config` 等已被强制排除）。⚠️ 主目录常有百万级文件（实测 216 万 → 一次搜索约 1 分钟），**建议指向你真正放文档的目录** |
| `MEMO_WORKSPACE_ROOT` | memo-bot 目录     | 搜索里加权的目录（一般无需改）                                                                                                 |
| `MEMO_SETTINGS_FILE`  | `settings.json` | 本机设置文件路径（配置中心网页与「设置」指令写的就是它）                                                                                    |
| `MEMO_IGNORE`         | 空               | **忽略表种子**（逗号分隔，中英文逗号都认）。命中规则的群 / 私聊消息一律跳过。改 `.env` 即生效，**「忽略」指令删不掉**（防误删把循环放出来）                                 |
| `MEMO_IGNORE_FILE`    | `ignore.json`   | 忽略表规则文件路径（由「忽略」指令维护）                                                                                            |

> 私有扩展（`extensions/local/`）需要的变量（如 `MEMO_FORTUNE_FILE`、`FA_ENV_ID`）由扩展自行读取，  
> 加在同一个 `.env` 里即可 —— 它们**不属于公开配置**。

### 可选（外部依赖定位，默认都走 PATH）

| 变量                     | 用途                                   |
| ---------------------- | ------------------------------------ |
| `MEMO_NODE`            | `node` 可执行文件（渲染成图片用到）                |
| `MEMO_CHROME`          | 浏览器可执行文件（找不到时自动试 Chrome/Edge 常见安装位置） |
| `MEMO_PLAYWRIGHT_CORE` | `playwright-core` 包目录                |

找不到时**明确报错并列出已尝试的路径**，不再静默失败。

## 可扩展性：加你自己的指令

内置指令之外，你可以**不改任何公开代码**就加自己的指令 —— 放在 `extensions/local/` 即可。  
该目录已在 `.gitignore` 里，**不会进公开仓库**（本地 bot = 公开代码 + 你的私有扩展）。

### 三步加一条指令

1. 在 `extensions/local/` 新建 `myext.py`；
2. 写一个 `register(reg)`；
3. 重启 bot，`帮助` 菜单会自动带上你写的 `help` 行。

```python
# extensions/local/myext.py
def register(reg):
    def handle(text, mentioned):
        return "👋 你好，这是一条自定义回复"
    reg.add(["打招呼", "hi"], handle, help="打招呼 —— 回你一句")
```

### handler 契约

```python
def handle(text, mentioned) -> str | list[str] | None
```

| 参数 / 返回        | 含义                            |
| -------------- | ----------------------------- |
| `text`         | 已剥掉 @ 标记的指令全文（如 `"我的指令 参数"`）  |
| `mentioned`    | 是否在 @机器人 场景（非 @ 时群里普通聊天也会走到这） |
| 返回 `None`      | 不处理，继续走后面的逻辑                  |
| 返回 `str`       | 回一条消息                         |
| 返回 `list[str]` | 依次回多条（`msg_seq` 自动递增）         |

- handler 是**同步函数**，框架用线程执行 → 里面可以直接做阻塞操作（读硬件 / 调外部命令），**不会卡住机器人心跳**。
- 想在非 @ 场景不接话？在 handler 里 `if not mentioned: return None`。

### 常用能力

| 通过 `reg`                           | 说明                                       |
| ---------------------------------- | ---------------------------------------- |
| `reg.add(names, handler, help="")` | 注册指令（`names` 为 str 或 list[str]，**精确匹配**） |
| `reg.api.search_files(q, limit=5)` | 按文件名/路径模糊搜配置的根目录                         |
| `reg.api.SEARCH_ROOT`              | 当前搜索根                                    |

### 加载与容错

- `extensions.load()` 依次加载 `extensions/*.py` 与 `extensions/local/*.py`。
- 某个扩展导入失败 / `register()` 抛异常 → **只打印 warning，不影响 bot 启动**，其余扩展照常生效。
- 精确匹配时**后注册者优先**，所以私有扩展可以覆盖公开扩展的同名指令。

完整模板见 `extensions/example.py`；本机私有扩展清单见 `extensions/local/README.md`。

2. **配置**（两条路选一条）：
   - ✅ **推荐**：`python config-web.py` → 网页上填 AppID / AppSecret → 点「保存并重启机器人」；

3. 把机器人加入你的群，并在**群设置**里打开下面那两个开关。想用**私聊**，还要在 QQ 开放平台 → 功能配置里开启「单聊」。

### 开机自启（不绑定任何会话）

用 Windows 计划任务托管，登录即启动，且**不显示控制台窗口**（`pythonw.exe` + `--log` 写文件）。

> ✅ **最省事的做法**：打开配置中心 → 「⑥ 运行方式」→ 拨一下「开机自启」开关。  
> 它做的就是下面这段 PowerShell（等价），而且会实时显示当前是开还是关。

<details>

```powershell
# pythonw 路径：优先取 PATH 上的；否则改成你本机的 pythonw.exe 绝对路径
$py  = if (Get-Command pythonw -ErrorAction SilentlyContinue) { (Get-Command pythonw).Source } else { '<你的 pythonw.exe 路径>' }
$dir = '<仓库>\memo-bot'
$act = New-ScheduledTaskAction -Execute $py -WorkingDirectory $dir `
       -Argument ('-u "' + $dir + '\bot.py" --log "' + $dir + '\bot.out.log"')
$trg = New-ScheduledTaskTrigger -AtLogOn
$set = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
       -StartWhenAvailable -ExecutionTimeLimit ([TimeSpan]::Zero) `
       -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) -MultipleInstances IgnoreNew
Register-ScheduledTask -TaskName 'MoyuBot' -Action $act -Trigger $trg -Settings $set -Force
```

</details>

- 任务名 `MoyuBot`；查看状态：`Get-ScheduledTask -TaskName MoyuBot`；立刻跑：`Start-ScheduledTask -TaskName MoyuBot`。
- 日志：`memo-bot/bot.out.log`。
- 🔴 **同一时刻只能跑一个实例**（两个进程会各建一条 WS 连接、事件被抢）。改代码后要 `Stop-ScheduledTask` 再 `Start-ScheduledTask`（或配置中心点「重启」）。

## 与外部助手集成（可选）

bot 是纯本地进程，任何能在本机执行命令的程序都可以驱动它：

- **读备忘 / 灵感**：`python bot.py --list` 或读 `memos.db`。
- **处理灵感**：`python ideas.py --export` → 读导出的 md → 处理完 `--done/--decide/--drop` 回写。
- **发文件**：`python send_file.py --file <路径> --caption "说明"`。

「让助手把文件发到群」这种需求，本质是**助手在本机调用 `send_file.py`**，而不是 bot 反向驱动助手——  
因为 bot 只暴露 QQ 收发接口，不对外暴露本机控制能力。

## 定时巡检（可选）

可另起一个定时任务周期性跑 `ideas.py --export` 刷新灵感池、跟进备忘库，输出周报。  
纯本地、不调 AI，可按自己的节奏接。

## 两个入口为什么能并存

`bot.py`（收）走 WebSocket 网关常驻；`send_file.py`（发）走**纯 HTTP**（直接调 REST API，不建网关连接）。互不抢连接，可同时运行。

## 限制与注意

> 下面这几项开关都在**手机 QQ 的机器人设置页**里，具体位置见 [四步跑起来](#四步跑起来) 第 3 步的截图。

- **主动推送**：群需开启「机器人主动在群聊内发言」；**单聊无需开关**（实测可直接主动推送，有频控：个人认证 10/qps，未认证 5/qps + 30/qpm，单用户 20/qpm、每好友每天最多 1000 条）。群内未开启时会自动降级为被动回复（需 4 分钟内群里 @ 过 bot，`msg_id` 缓存在 `last_group_msg.json`）。`--passive` 可强制走被动回复。
- **全量群消息**：需群内开启「消息范围 = 全部消息」，且依赖 `install_group_message_parser()` 补的解析器。
- **私聊**：需在 QQ 开放平台开启「单聊」能力，且**对方要先私聊过机器人（并加了好友）** —— 这样才会出现在配置中心的「播报目标」列表里，也才有 `user_openid` 可发。私聊**可以主动推送**（见上条），所以启动播报 / 关机播报能直接私聊发过去；只是**群指令的回复**（发文件 / 发图）走被动回复，语义更准。
- 本地文件上传走官方 `/v2/{groups|users}/{openid}/files` 的 `file_data`(base64) 参数；200MB 上限。**群与单聊的上传接口相互独立，不能跨场景使用**。
- 上传必须带 `file_name`，否则 QQ 文件卡片显示「未命名」；`305013`（审核服务超时，**不是内容违规**）/ `850027`（发送超时）/ `40093001`（上传失败）会自动重试 2 次（间隔 1.5s）。
- **忽略表**：`MEMO_IGNORE`（`.env`）的规则指令删不掉，只有 `ignore.json` 里的能被「忽略 删除」/「忽略 清空」改；规则长度下限 2 字。
- 生产存储可把 `store.py` 换成任意数据库后端（接口不变）。

### 发版与「检查更新」

**版本号只有一处真源**：`memo-bot/VERSION`。`version.py` 的 `VERSION` 常量跟它一致（有测试盯着），
`_exe_poc/memo-bot.iss` 也**直接读那个文件** —— 所以安装包名字里的版本号不会跟代码脱节。

配置中心「⑦ 运行方式 → 检查更新」会去 jsdelivr 读远端的 `VERSION` 比一比。有新版本时页面会多出一个
**「⬇ 下载 v<新版本>」按钮**（可点、可右键复制链接），旁边还有 Releases 页面兜底入口。

**下载链接怎么来的**（`version.py`）：

| 情况 | 链接 |
| --- | --- |
| 默认 | `https://github.com/<repo>/releases/download/v<版本>/memo-bot-setup-v<版本>.exe` |
| 设了 `MEMO_DOWNLOAD_BASE=https://你的域名/dl` | `https://你的域名/dl/memo-bot-setup-v<版本>.exe` |

所以想换成**自己的服务器 / 对象存储**，只改一个环境变量，不用动代码。

**发版三步**（版本号改完再打包）：

1. 改 `VERSION`（和 `version.py` 的 `VERSION`），提交推送；
2. `python _build_dist.py` → `ISCC.exe memo-bot.iss`，产物是 `output\memo-bot-setup-v<版本>.exe`；
3. 在 GitHub 建一个 **tag 为 `v<版本>` 的 Release**，把那个 exe **原样上传成资产**。

🔴 第 3 步的 tag 和文件名**必须**和 `version.py` 里的模板一致（`v{ver}` / `memo-bot-setup-v{ver}.exe`），
否则用户点「⬇ 下载新版」会 404。测试里有一条护栏盯着 `.iss` 和 `version.py` 这两处不许写歪。

> 安装包放在 GitHub Releases 上，国内下载**可能慢或连不上**。介意的话就把 exe 传到自己的服务器 /
> 对象存储，然后设 `MEMO_DOWNLOAD_BASE` 指过去 —— 文件名保持一致即可。
