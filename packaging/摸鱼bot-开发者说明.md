# 摸鱼bot 开发者说明 —— 自定义指令怎么写

> 这份文档给**要写指令的人**看。只想装别人写好的指令 → 看 README 的“可扩展性”一节。
> 本文只讲规则与契约；普通使用说明见 README 和安装指南。

---

## 一、三分钟上手

在 `extensions/local/` 新建一个 `.py`，里面写一个 `register(reg)`：

```python
# extensions/local/greet.py
def register(reg):
    def handle(text, mentioned):
        return "👋 你好，这是一条自定义回复"

    reg.add(["打招呼", "hi"], handle, help="打招呼 —— 回你一句")
```

重启机器人，群里发 `打招呼`（或 `@机器人 打招呼`）就回你一句；
`帮助` 菜单里会多出「打招呼 —— 回你一句」这一行。

> 改动 `extensions/` 下的文件**必须重启机器人**才生效 —— 指令是启动时注册的。

## 二、指令放在哪：一个「扩展包」的两种形态

| 形态 | 路径 | 怎么来 |
| --- | --- | --- |
| **单文件包** | `extensions/local/我的指令.py` | 自己写，或在配置中心「⑨ 自定义指令」导入一个 `.py` |
| **目录包** | `extensions/local/我的指令/`（放一个或多个 `.py`，可带自己的数据文件） | 在配置中心导入一个 `.zip` |

判定规则只有一处：`extensions.scan_dir()`（加载器与配置中心共用它）。

- **一级 `*.py`**（`_` 开头除外）= 单文件包；
- **一级子目录**（`.` / `_` 开头除外）里含 `*.py` = 目录包。

🔴 所以：**下划线开头的文件与目录不会被扫描**。想放私有工具 / 草稿，就用 `_xxx.py`。

`extensions/local/` 已在 `.gitignore` 里，**你的指令不会跟着程序发布出去**；公开仓库只有一份空模板 `extensions/example.py`。

## 三、`register(reg)` 契约

- 模块里**必须有一个 `def register(reg)`**（配置中心导入时会按这行做静态检查，没有就拒收）。
- 模块顶层（import 时）**不要做任何耗时 / 阻塞的事** —— 见第五节。
- 一个模块可以注册多条指令。
- `register()` 里抛异常 = 这个包加载失败，原因会显示在配置中心页面上。

### `reg.add(names, handler, help="")`

| 参数 | 说明 |
| --- | --- |
| `names` | `str` 或 `list[str]`：指令词与它的别名。**空串 / 全空白会被拒**（`ValueError`） |
| `handler` | 处理函数，**必须可调用**（否则 `TypeError`） |
| `help` | 帮助菜单里显示的那一行。**留空则不出现在帮助菜单里**（指令照常可用） |

**匹配是精确匹配**：整条消息（去掉 @ 标记、去首尾空白后）**等于**某个指令词才命中。

- ✅ `打招呼` 命中 `["打招呼"]`
- ❌ `打招呼 你好` **不命中**（带了参数就是另一条消息了）

🔴 想让指令带参数，得把整句都当成指令词注册（例如 `["查余额", "查余额 3"]`），
或者把参数写成独立的别名。**目前没有「前缀匹配 + 参数」的机制**，这是刻意的（避免普通聊天被误吞）。

**同一条指令被注册多次时，后注册的优先**（`reg.match()` 逆序查找）。
加载顺序是：`extensions/*.py` → `extensions/local/*.py` → `extensions/local/<包名>/*.py`，
所以**私有扩展可以覆盖公开扩展的同名指令**；同一个包内也是后面的盖前面的。
配置中心会把「和别人撞了指令名」标出来。

## 四、`handler` 契约

```python
def handle(text, mentioned) -> str | list[str] | None
```

| 入参 / 返回 | 含义 |
| --- | --- |
| `text` | 已剥掉 `@` 标记的**整条消息全文**（首尾空白已去） |
| `mentioned` | 是否在 `@机器人` 场景。群里非 @ 的普通聊天也会走到扩展指令这一层 |
| 返回 `None`（或 `""` / `[]`） | **不接话**，流程继续往下走（后面还有内置指令会试着匹配） |
| 返回 `str` | 回一条消息 |
| 返回 `list[str]` | **依次**回多条（`msg_seq` 自动递增） |

**必须遵守：**

1. 🔴 **handler 必须是同步函数，不能是 `async def`。**
   框架用 `asyncio.to_thread()` 在线程里跑它 —— 返回 coroutine 对象会被当成一条消息内容，直接报错。
2. 🔴 **可以做阻塞操作。** 因为是跑在独立线程里，读硬件、调外部命令、发 HTTP 请求都不会卡住机器人心跳。
   但也别跑几分钟不返回 —— 群里的表现是「这条指令没反应」。
3. **异常自己兜住。** handler 抛异常时，机器人会回一句
   `（扩展指令执行失败：<异常类型>: <异常信息>）`。想给用户看更友好的话，就自己 `try/except`。
4. **只返回 `str` / `list[str]` / `None`。** 返回数字、字典、对象都不是受支持的用法。
5. **想只在 @ 时接话**：`if not mentioned: return None`。
6. 🔴 **起外部命令必须带 `CREATE_NO_WINDOW`。**
   机器人跑在 `pythonw` 下、**本身没有控制台**，你 `subprocess.run(...)` 一个控制台程序
   （`node` / `nvidia-smi` / `taskkill` / `tcb`…），Windows 会给它新建一个黑窗口 ——
   用户每发一次指令就看到窗口闪一下。正确写法：

   ```python
   _NO_WINDOW = 0x08000000 if os.name == "nt" else 0     # CREATE_NO_WINDOW
   subprocess.run(cmd, capture_output=True, text=True,
                  encoding="utf-8", errors="replace",   # 中文 Windows 默认 GBK，会解码炸
                  creationflags=_NO_WINDOW)
   ```

   另外 `stdout` 一定要显式指定 `encoding="utf-8"`：bot 进程的默认编码是 `cp936`，
   子进程输出里有非 GBK 字节时，不指定就会解码成空字符串（看着像「命令没返回」）。

**群和私聊都会走到这里**，同一个 handler 两处通用。
私聊里非指令的文本会被机器人当「灵感」收下，所以指令词别起得太随意（比如「好」「在吗」）。

## 五、🔴 执行顺序：扩展指令在指令链的哪一环

机器人处理一条消息的顺序（`bot.py::route_message`）：

```
0)   忽略表
0.5) 有待选文件时，先解析「选哪个」
0.6) 设置指令
1)   发文件
1.5) ★ 扩展指令（你写的就是这一环）
1.7) 摸鱼
1.8) 回旋镖
1.9) 导出
2)   查备忘 / 查灵感 / 搜索灵感 / 你好 / 帮助
4)   记备忘
4.5) 兜底
5)   非 @ 的普通文本 → 自动收作「灵感」
```

由此得出两条实用规则：

- 🔴 **扩展抢不过前面那几个**：`忽略`、`设置`、`发文件` 的指令词你抢不走 —— 撞名了永远轮不到你。
- 🔴 **扩展能盖住后面的**：`摸鱼`、`回旋镖`、`导出`、`查备忘`、`查灵感`、`你好`、`帮助`、`备忘`
  这些，扩展先匹配到就 `return` 了，内置那一步不会再执行。
  但注意：**只有 handler 真的返回了内容才 `return`**；返回 `None` 会让流程继续往下走，
  于是内置那一步照样会处理。

## 六、能用什么：`reg.api`

```python
api = reg.api                      # 可能是 None（见下）
api.search_files("关键词", limit=5)  # → [(相对路径, 绝对路径), …]
api.SEARCH_ROOT                    # 「发文件」当前配置的搜索根（默认用户主目录）
```

- 🔴 **`reg.api` 可能是 `None`。** 配置中心为了在页面上显示「这个包装了哪些指令」，
  会在**子进程**里把扩展试加载一遍，那时 `api=None`。
  **写代码时必须容忍它为空**（本机私有扩展 `fortune.py` 就是这么写的）：

  ```python
  if api is not None:
      for rel, full in api.search_files("关键词", limit=5):
          ...
  ```

- 除 `api` 之外，**不要依赖机器人的内部模块或私有变量** —— 那些不承诺稳定，改版就可能没。
  需要什么能力，通过 `api` 提出来加。

## 七、导入闸门：配置中心会拦什么

导入（`.py` / `.zip`）时的校验，写包之前先过一遍：

| 项 | 规则 |
| --- | --- |
| 扩展名 | 只收 `.py` 与 `.zip` |
| 单个 `.py` 体积 | ≤ **1 MB** |
| `.zip` 体积 | ≤ **8 MB**（**解压后**总量），条目数 ≤ **300** |
| 必须含 `register` | 内容里要有 `def register(`（正则按行首匹配），否则拒收 |
| 路径安全 | 拒绝绝对路径、`..`、盘符、符号链接 |
| 顶层目录 | zip 里**只有一个顶层目录**时会自动剥掉（`我的包/a.py` → `a.py`），多套一层没关系 |
| 文件名 | 只保留 `[0-9A-Za-z_-]`，去首尾 `-_`，数字开头补 `ext_`，最长 60 字符 |
| 重名 | 默认拒（返回 409），确认覆盖才会替换 |

- 文件名收拾的副作用：`../../evil.py` 会落成 `local/evil.py`，**跑不出 `local/`**。
  中文文件名会被过滤成空 → 落成 `ext.py`。**建议直接用英文名。**
- 目录包里除 `.py` 外的文件（README、数据文件）会被原样带进去，页面上会列出来。
- **「移除」不是真删** —— 文件被挪进 `extensions/.removed/`，想找回还在。

## 八、🔴 一条硬规则：模块顶层别做重活

配置中心点开「⑨ 自定义指令」时，会**在一个子进程里把每个 `.py` 试加载一遍**，
用来读出「这个包注册了哪些指令」。这个子进程**只等 8 秒**。

- ❌ 顶层 `time.sleep(30)`、`requests.get(...)`、连数据库、读大文件 —— 会让探测超时，
  页面上显示「加载超时（超过 8 秒没返回）」，用户以为你的包坏了。
- ✅ 把耗时操作放进 **handler 里**，或者做成**懒加载**（第一次用到才初始化）。
- ✅ 结果按 `(修改时间, 体积)` 缓存，所以同一份文件第二次打开页面是秒回。

同样地：顶层**不要** `print()` 一堆东西、不要弹窗、不要起线程 / 起进程、不要读 `input()`。

## 九、打包发布

1. 单条指令：直接把 `.py` 发给别人。
2. 一包指令：把文件放进一个文件夹，**压成 `.zip`**（可以多套一层目录，导入时会自动剥掉）。
   里面可以放 README、示例数据文件 —— 除 `.py` 外的文件不会被加载，只是跟着走。
3. 🔴 **压缩包里绝不能有密钥。** 别人导进去就等于拿到了你的凭据。
   需要密钥的指令，让使用者自己配环境变量（本机私有扩展就是这么做的）。

## 十、自测清单

发布前逐条过：

- [ ] 文件名是**英文**（中文会被过滤掉）。
- [ ] 模块里有 `def register(reg)`，且在文件里**行首**能匹配到（前面可以有空格 / Tab）。
- [ ] `register()` 里**没有**会抛异常的东西。
- [ ] 顶层**没有**耗时 / 阻塞 / 输出。
- [ ] 用到 `reg.api` 的地方**判了空**。
- [ ] handler 是**同步函数**（不是 `async def`）。
- [ ] handler 里 `try/except` 兜住了外部调用（网络、文件、子进程）。
- [ ] 返回值只有 `str` / `list[str]` / `None` 三种。
- [ ] 指令词**没和内置指令撞**（见第五节顺序表），也没和别人的包撞。
- [ ] 指令词**不会误吞普通聊天**（比如「好」「在吗」「好的」这种别注册）。
- [ ] 在配置中心「⑨ 自定义指令」页导入后，**页面上能看到指令名、没有报错**。
- [ ] 重启机器人后，群里和私聊各试一遍。
- [ ] `帮助` 菜单里出现了你写的 `help` 行（没写 `help` 就不会出现，这是正常的）。
